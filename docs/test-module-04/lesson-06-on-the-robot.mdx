```python
def turn_to(current_heading, desired_heading):
    """Turn clockwise a quarter turn at a time until
    current_heading is desired_heading; return the new
    heading."""
    while current_heading != desired_heading:
        turn_clockwise()
        current_heading = (current_heading + 1) % 4
    return current_heading

def drive_path(path, current_position, current_heading):
    """Turn and drive through every intersection in path;
    return the final position and heading."""
    for next_pos in path:
        desired_heading = get_desired_heading(current_position, next_pos)
        print("moving: from", current_position, "to:", next_pos,
              "heading:", HEADING_NAMES[desired_heading])
        current_heading = turn_to(current_heading, desired_heading)
        track_to_intersection()
        current_position = next_pos     # the robot is there now
    return current_position, current_heading
```

Work out first, on paper, when counterclockwise is actually shorter: try the four

exactly those cases, keeps `current_heading` up to date either way, and still returns it.
Check it on screen first: add a `fake_turn_counterclockwise()` that prints

<TeacherNote title="Challenge answer (teacher copy)">

Counterclockwise wins in exactly one case: when `desired_heading` is one step to the left,
which is three clockwise steps around, `(current_heading + 3) % 4`. Turning around is a tie.
Check that case first and let the loop finish the job; after the left turn its condition is
already False:

```python
def turn_to(current_heading, desired_heading):
    """Turn until current_heading is desired_heading, the
    short way round; return the new heading."""
    if desired_heading == (current_heading + 3) % 4:   # left
        turn_counterclockwise()
        current_heading = desired_heading
    while current_heading != desired_heading:
        turn_clockwise()
        current_heading = (current_heading + 1) % 4
    return current_heading
```

Watch for a version that turns left and then *also* loops because it forgot to update
`current_heading`.

<OptionalExtension title="The Navigator class, and what self really is">

If you did the Module 2 class extensions, the driving functions can become a `Navigator`
class. It is the first class in the course whose constructor takes real parameters, which
makes it the right moment to say what `self` actually is.

Back in Lesson 2-7, the class was a blueprint and the objects were the houses built from it.
Here is the same picture with one thing added: every house has an **address**.

<Figure
  src="/img/lesson-m4-06/house-address.svg"
  alt="A blueprint labeled 'class House:' listing __init__(self, color) and paint(self). Below it, three houses built from the plan, each with an address plaque: red at 12 Oak, yellow at 48 Elm, blue at 7 Pine, with the code that built each one. At the bottom, the call elm.paint() with an arrow to the yellow house and the note: inside paint(), self is 48 Elm — the one house this call is about."
  caption="The plan says what painting is. The address says which house. When you call elm.paint(), self is 48 Elm, nothing else."
/>

The plan says what "paint" means, the same for every house. `elm.paint()` means "paint the
house at 48 Elm", and inside `paint()`, `self` is that address. Call `oak.paint()` and the
same code runs with `self` meaning 12 Oak. **`self` is the address of the one object this
call is about.** `self.position` is "the position of this navigator, not any other".

A method is a **work order written once for every house, with a blank for the address.**
That's why `self` is the first parameter in the `def`, and why it's absent from the call:
Python fills the blank in from the object you pointed at. Two errors become easy to read:

- `def paint():` with no `self`: Python says *"takes 0 positional arguments but 1 was
  given"*. It tried to fill in the blank and found none.
- `color` instead of `self.color` inside the method: *"NameError: name 'color' is not
  defined"*. A color with no address attached.

Now the Navigator. Its constructor takes the start position and heading and stores them at
its own address. Paste this in place of `get_desired_heading()`, `turn_to()` and
`drive_path()` (keep `HEADING_NAMES` and your tests), and move your bodies into the methods.

```python
# ===== NAVIGATOR (class version) =====
# One Navigator object owns the robot's position and heading.
# It HAS a LineTrack (built in __init__) and gives it the
# driving orders; it is told where to go and keeps its own
# record of where it got to.
class Navigator:
    def __init__(self, start, heading):
        self.position = start
        self.heading = heading
        self.line_track = LineTrack()        # has-a LineTrack

    def get_desired_heading(self, next_pos):
        # your function; position is self.position now, so
        # it is no longer a parameter
        pass

    def turn_to(self, desired_heading):
        # your function, with self.heading in place of the
        # parameter and self.line_track. in front of the
        # turn; it STORES the new heading, not returns it
        pass

    def drive_path(self, path):
        # your function, with self. in front of position,
        # heading and the two LINE TRACKING calls; it stores
        # the final position instead of returning it
        pass

navigator = Navigator((0, 0), 0)
```

The two parameters land in `self.position` and `self.heading`, and from then on every method
reads and updates *those*. That's why the signatures shrank, and why nothing is returned:
the record lives at the object's address, and the main program reads `navigator.position`
whenever it wants to know.

<Reveal title="Check your Navigator" hint="translate all three methods first">

```python
    def get_desired_heading(self, next_pos):
        x, y = self.position
        next_x, next_y = next_pos
        if next_y > y: return 0   # North
        if next_x > x: return 1   # East
        if next_y < y: return 2   # South
        if next_x < x: return 3   # West
        raise ValueError(str(next_pos) + " is not one step from " + str(self.position))

    def turn_to(self, desired_heading):
        while self.heading != desired_heading:
            self.line_track.turn_clockwise()
            self.heading = (self.heading + 1) % 4

    def drive_path(self, path):
        for next_pos in path:
            desired_heading = self.get_desired_heading(next_pos)
            self.turn_to(desired_heading)
            self.line_track.track_to_intersection()
            self.position = next_pos
```

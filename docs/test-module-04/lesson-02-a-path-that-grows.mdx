## One step at a time

Each step moves the robot to a neighboring intersection, so **exactly one of x or y
changes, by 1**. Never both: that would be a diagonal, and the robot can't drive one.

<Figure
  src="/img/lesson-m4-03/one-step.svg"
  alt="A 3 by 3 grid with the robot's intersection (1, 1) in the middle. Red arrows go right to (2, 1), x + 1, and left to (0, 1), x - 1. Green arrows go up to (1, 2), y + 1, and down to (1, 0), y - 1. A dashed diagonal to (2, 2) is crossed out: x and y both change, so it is not one step."
  caption="One step changes x or y by 1, never both."
/>

The Manhattan rule from Lesson 4-0: **step across until x is right, then step up or down
until y is right.**

## A list can grow

In Lesson 4-1 you wrote a list out in full. A planner can't: it doesn't know the path
until it works it out. So it starts with an **empty list** and adds one position at a
time with `append()`, which puts an item on the **end**:

```python
path = []
path.append((1, 0))
path.append((2, 0))
print(path)          # [(1, 0), (2, 0)]
print(len(path))     # 2
```

`len()` counts the items. Mind the double parentheses in `path.append((1, 0))`: the outer
pair belongs to `append()`, the inner pair is the tuple.

### Step 2 · Let a loop do the appending

Look at rows 1 and 2 of your trace: add 1 to x, write down the new position, and again,
until x is right. That's a `while` loop.

<Figure
  src="/img/lesson-m4-03/trace-to-loops.svg"
  alt="The trace table for (0, 0) to (2, 3). Rows 1 and 2, in red, say x + 1 and are bracketed to loop 1: while x < dest_x, x = x + 1, path.append((x, y)). Rows 3 to 5, in green, say y + 1 and are bracketed to loop 2, the same loop for y."
  caption="Each row is one trip around a loop."
/>

To add 1 to x, the function needs x on its own. **Unpacking**, from Lesson 4-1, takes a
tuple apart:

```python
x, y = start                     # start is (0, 0): x is 0, y is 0
dest_x, dest_y = destination     # (2, 3): dest_x is 2, dest_y is 3
```

`x` and `y` are where the plan has got to. They start as the start and change by 1 on
every move. After each move, `(x, y)` puts them back together as a **new tuple** for the
path.

Replace the whole `compute_manhattan_path()` function with this. The east loop is written for you; north is yours
in Step 3. Add `test_planner()` under it.

```python
def compute_manhattan_path(start, destination):
    """Return the (x, y) steps from start to destination, across
    first, then up or down. The start itself is not in the list."""
    print("computing path from:", start, "to:", destination)
    path = []
    x, y = start              # where the plan is now
    dest_x, dest_y = destination   # where it is going

    # East: keep stepping right until x matches dest_x
    while x < dest_x:
        x = x + 1             # one step right
        path.append((x, y))   # record the new spot

    # North: copy east, but step y until it matches dest_y

    return path

def test_planner():
    print(compute_manhattan_path((0, 0), (2, 3)))
    print(compute_manhattan_path((0, 2), (3, 2)))
    print(compute_manhattan_path((2, 0), (2, 3)))
```

Before you run it, trace the three trips in `test_planner()` on paper. Then set the run
line to `test_planner()` and run it.

**What correct looks like:** each trip prints what was asked, then the path. Only the east
loop exists, so:

```

[(1, 0), (2, 0)]
computing path from: (0, 2) to: (3, 2)
[(1, 2), (2, 2), (3, 2)]
computing path from: (2, 0) to: (2, 3)
[]
```

The first trip goes right two and stops. The second needs no move up, so it's already
complete. The third only goes up, so nothing is appended.

## Why a new tuple every step

Could the loop just change the x inside one tuple? Try it in the shell:

```python
spot = (2, 3)
spot[0] = 5      # TypeError: 'tuple' object does not support item assignment
```

A tuple **can't be changed** once it's made. That's right for a position: `(2, 3)` should
always mean the same intersection, however many lists it's in. A list is the opposite: it
can grow. So a *position* is a tuple, and a *path* is a list of tuples.

<KnowledgeCheck
  question="Which is true?"
  options={[
    {text: 'A tuple can grow with append(); a list cannot'},
    {text: 'A list can grow and change; a tuple stays as it was made', correct: true},
    {text: 'Lists and tuples are the same thing with different brackets'},
    {text: 'A list can only hold numbers'},
  ]}
  explanation="Lists use square brackets and can change, which suits a path that is built step by step. Tuples use parentheses and can't change, which suits a position."
/>

<TeacherNote title="What to watch">

"Empty list, append inside a loop" is the pattern the rest of the course builds paths
with. Step 1 is deliberately clumsy: five typed appends make students want the loop, and
the repeated path shows why a planner must use its parameters. Keep it to five minutes.

Take real time on the double parentheses in `path.append((x, y))`, and on Step 3: the

<TeacherNote title="Solution (teacher copy)">

The MANHATTAN PLANNER section as this lesson leaves it. The NAVIGATOR section and the
main program are unchanged from Lesson 4-1.

```python
# ===== MANHATTAN PLANNER =====
# Plans a route across the grid: given where the robot is and
# where it should go, returns the list of (x, y) tuples to
# drive to. Nothing in here touches a sensor or a motor.

def compute_manhattan_path(start, destination):
    """Return the (x, y) steps from start to destination, across
    first, then up or down. The start itself is not in the list."""
    print("computing path from:", start, "to:", destination)
    path = []
    x, y = start              # where the plan is now
    dest_x, dest_y = destination   # where it is going

    # East: keep stepping right until x matches dest_x
    while x < dest_x:
        x = x + 1             # one step right
        path.append((x, y))   # record the new spot

    # North: copy east, but step y until it matches dest_y
    while y < dest_y:
        y = y + 1             # one step up
        path.append((x, y))

    return path

def test_planner():
    print(compute_manhattan_path((0, 0), (2, 3)))
    print(compute_manhattan_path((0, 2), (3, 2)))
    print(compute_manhattan_path((2, 0), (2, 3)))
```

</TeacherNote>

## Wrap-up

- How does the planner build a path? (Start with `[]`, and `append()` one position on every trip around a loop.)
- What does `x, y = start` do? (Unpacks the tuple: x gets the first number, y the second.)
- Why isn't the start in the path? (The robot is already there; the path lists where it drives to.)
- What still doesn't work? (Trips that go left or down: both loops are skipped.)

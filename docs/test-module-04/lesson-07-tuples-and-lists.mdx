## Tuple or list?

| | Tuple | List |
|---|---|---|
| Written with | `( )` | `[ ]` |
| Can it change? | No | Yes: it can grow, and items can be replaced |
| Index, unpack, `==`, `for`, `len()` | Yes | Yes |
| `append()` | No | Yes |
| In your program | a position, a pose | a path, the destinations, the heading letters |

The rule of thumb: a **tuple** is one thing made of a fixed number of parts, like a
position. A **list** is any number of things in order, like the stops on a route.

## Activity · Predict, then run

Open a **new file**, not `robot.py`. For each numbered line, write down what you expect
it to print. Then type the program in, run it, and compare. One line stops the program
with an error: say which, and why.

```python
path = [(1, 0), (2, 0), (2, 1)]
print(len(path))                               # 1
print(path[0])                                 # 2
print(path[2][1])                              # 3
x, y = path[1]
print(x + y)                                   # 4
path.append((2, 2))
print(len(path), path[3])                      # 5
print(path == [(1, 0), (2, 0), (2, 1)])        # 6
path[0] = (0, 1)
print(path)                                    # 7
path[0][0] = 5                                 # 8
```

<Reveal title="Check your predictions" hint="write all eight down and run it first">

1. `3`: three items.
2. `(1, 0)`: index 0 is the first item.
3. `1`: `path[2]` is `(2, 1)`, and its index 1 is y.
4. `2`: `path[1]` is `(2, 0)`, so x is 2 and y is 0.
5. `4 (2, 2)`: the list grew, and the new item is at the end.
6. `False`: the list has four items now, so it no longer equals the three-item list.
7. `[(0, 1), (2, 0), (2, 1), (2, 2)]`: a list item **can** be replaced.
8. `TypeError: 'tuple' object does not support item assignment`. `path[0]` is a tuple,
   and a tuple can't be changed. Line 7 worked because it replaced a whole item of the
   **list**; line 8 tries to change one part of a **tuple**.

</Reveal>

## What the variable actually holds

One idea is still missing, and it explains something you have already seen.

In Lesson 1-9, a variable was a named location in memory, and `=` stored a value
there. For a number, that's the whole story.

A list grows, but a memory location is a fixed size. So the list lives somewhere else
in memory, and the variable holds its **address**. An address stored in a variable is
called a **reference**. It matters when two variables hold the same address:

```python
a = 5
b = a                     # copies the VALUE: two 5s

path = [(1, 0)]
same_path = path          # copies the ADDRESS: still one list
same_path.append((2, 0))
print(path)               # [(1, 0), (2, 0)]  <- path changed too
```

### Assigning versus changing

In Lesson 4-1, `current_position = next_pos` inside `drive_path()` did **not** change the
main program's `position`. That still holds, for lists too. The difference is between two
things a function can do with a parameter:

```python
def move(spot):
    spot = (9, 9)             # ASSIGNS: spot now holds something else

def extend(steps):
    steps.append((9, 9))      # CHANGES the list steps refers to

here = (1, 1)
move(here)
print(here)                   # (1, 1)  -- untouched

route = [(1, 1)]
extend(route)
print(route)                  # [(1, 1), (9, 9)]  -- changed
```

`=` stores a new value in the function's own variable, and the caller never sees it.
`append()` goes to the list itself, and there is only one list. A tuple can't be changed
at all, so a function can never alter a position you hand it.

This isn't a trap; the course relies on it. In Module 5 a planner sees each obstacle
you add to your list because it holds the list's address, not a copy.

<TeacherNote title="Nothing from Lesson 1-9 gets taken back here">

Worth being explicit with students: this section **adds** to Lesson 1-9, it doesn't
correct it. A variable is still a named memory location, and `=` still works out
the right side and stores the result there. The only new fact is what the stored
value *is* for a list: the address that was printed on the location all along.

If a student asks why the address exists at all, the physical reason is the honest
one: a location is a fixed size, a list can grow, so the list has to live somewhere
with room to grow and the location keeps the number that says where.

The demo that lands: two students each hold a slip of paper with the same post
office box number on it. One of them goes and puts something in the box. The other
one's slip hasn't changed, but what they find when they open the box has. Then ask
what would have to be different for them to have *separate* boxes.

"Assigning versus changing" ties this to the Lesson 4-1 dropped-return bug. Run `move()`
and `extend()` live; the two printouts side by side do more than the explanation.

Don't teach `copy()` or slicing: nothing in this course needs an independent copy, and
the sharing is load-bearing in Module 5.

</TeacherNote>

## Wrap-up

- Tuple or list: which for a position, which for a path, and why? (Tuple: a fixed pair that shouldn't change. List: any number of steps, built up one at a time.)
- Name three things you can do with both. (Index, unpack, compare with `==`, loop with `for`, count with `len()`.)
- What can a list do that a tuple can't? (Change: `append()`, or replace an item.)
- If two variables refer to the same list and you append through one, what does the other see? (The change: there is only one list, and both variables hold its address.)

Your `square` function always draws the *same size* square. What if you want
a big one, then a small one? You could write `square_big` and
`square_small`… but that's the copy-paste problem all over again. The fix is
a **parameter** — a slot you fill in each time you call the function.

<Objectives>

By the end of this lesson you will be able to:

- Explain what a parameter is — an input that changes what a function does
- Add a parameter to a Blockly function using the **gear icon** and the mutator bubble
- Find that parameter in the **Variables** palette and use its value inside the function body
- Call one function with different **arguments** to get different results

</Objectives>

## One function, any size

A parameter is like a blank in a recipe: instead of "add 1 cup of sugar," it says
"add *this much* sugar," and you decide how much each time you cook. For our square
function, the blank is the side length — we'll name the parameter `side_length`:

<BlockShot
  src="/img/blocks/programs/square-function.png"
  alt="A square function that takes a side-length parameter; the Straight block's cm uses the parameter, and a call passes 35"
  caption="The square function with a side_length parameter — the Straight block's cm holds the parameter instead of a number — and a call that passes 35."
/>

See how the **Straight** block's *cm* slot holds the parameter instead of a fixed
number, and the call at the bottom fills it in with `35`. Now one function draws
every size — just pass a different value each time you call it:

<BlockProgram
  blocks={[
    {name: 'call_square_35', alt: 'square call block passing side_length 35', note: 'medium'},
    {name: 'call_square_60', alt: 'square call block passing side_length 60', note: 'big'},
    {name: 'call_square_20', alt: 'square call block passing side_length 20', note: 'small'},
  ]}
  caption="One function, three sizes. Only the number in the socket changes."
/>

Getting there takes two moves that aren't obvious from looking at the blocks:
first you **add** the parameter to the function, then you **use** its value inside
the body. They happen in two different places, which is why it's easy to do one and
forget the other.

Here's the whole build, start to finish — about a minute and a half, no sound.
Watch it once for the shape of it, then work through the written steps below at
your own pace.

## Adding the parameter: the gear icon

Look at the top-left corner of your `square` definition block. There's a small
blue **gear icon**. Most blocks don't have one — the gear means "this block can
change shape," and a function's shape is exactly what you're about to change.

**1 · Click the gear.** A small bubble opens next to the block with its own tiny
workspace. In the grey strip on the left of the bubble is a block that says
**input name: x**. To its right is a block labelled **inputs** with an empty notch
inside it.

**2 · Drag `input name: x` into the `inputs` block.** Grab it from the grey strip and
snap it into the notch. Watch the definition block *behind* the bubble as you let go
— it grows a new row reading **with: x**. That's your parameter. It already exists;
it just has a terrible name.

<Figure
  src="/img/lesson-04/mutator-bubble.jpg"
  alt="The mutator bubble open below the square definition block: an input name block held inside the inputs block, and the definition above now reading 'to square with: x'"
  caption="Snap the input into the inputs block. The function grows a 'with:' row the moment it connects."
/>

**3 · Rename it.** Click the word `x` on the block you just dropped in, type
`side_length`, and press Enter. Use underscores, not spaces, and pick the name you'd
want in Python later, because in Lesson 1-10 you'll write this same function in text.
Short names are worth a thought here: the name rides along on the definition, on
every call block and on the variable block you'll drag into the body, so a long one
makes for wide blocks.

**4 · Close the bubble** by clicking the gear again. Your definition now reads
**to square with: side_length**.

Need a *second* parameter? Open the gear again and stack another **input name**
block underneath the first. The top-to-bottom order in the bubble is the
left-to-right order of the arguments, so it matters — `polygon (sides,
side_length)` in the next lesson is not the same function as
`polygon (side_length, sides)`.

## Using the parameter: the Variables palette

The function now *accepts* a side length, but the **Straight** block inside it is
still set to a hard number, so nothing has actually changed yet. You need a block
that says "whatever value was passed in" — and that block is waiting in the palette.

Open the **Variables** category, near the bottom of the palette. Past *Create
variable…* and the **set** and **change** blocks, there's a small rounded block
named **side_length**. Adding the parameter created it; you don't have to make it.

Every variable block carries a dropdown arrow, so if you grab the wrong one — easy
once a project has a few variables with similar names — you can switch it from the
dropdown instead of starting over.

<Figure
  src="/img/lesson-04/variables-palette.jpg"
  alt="The Variables category open in the XRP Code palette, listing several variable blocks including side_length, with the cursor on it"
  caption="A parameter shows up in Variables automatically — that rounded block is how you read its value. This workspace has a few half-typed leftovers too, which is exactly why you read the name before you drag."
/>

Drag `side_length` into the **cm** slot of the Straight block, straight on top of the
number sitting there. The number doesn't pop out and it isn't deleted — it's tucked
underneath, and it comes back if you ever pull the variable out again.

You can use the same parameter as many times as you like inside the function.

Now the calls. Open the **Functions** category and the call block there has changed
shape too — it reads **square with: side_length** and carries a socket for the value.
Drag one out, type `20` into the socket, drag out a second and type `30`, and snap
them together into a stack.

<Figure
  src="/img/lesson-04/two-calls.jpg"
  alt="The finished square function with a Repeat 4 around Straight and Turn, and below it two stacked call blocks passing 20 and 30"
  caption="The finished function, and below it two calls — 20 cm and 30 cm. Two sizes, one function. This is the payoff."
/>

<TeacherNote title="Demo this one live — slowly">

This is the one piece of Blockly UI that nobody discovers on their own. Project it
and narrate each move, especially the mutator bubble: students expect a menu or an
"Add Input" button, and instead they have to **drag a block inside another block**
in a floating mini-workspace. Several will drop the input *next to* the `inputs`
block rather than inside it and see nothing happen — the tell is a definition block
with no `with:` row.

The screencast at the top of this section is silent by design — project it, pause it
wherever you want to talk, and let it run again. It's also the fastest way to get a
student who fell behind back to the same place as everyone else.

Two more predictable snags. (1) They rename the input but never visit **Variables**,
so the body still uses a fixed number — the function ignores its argument, and the
symptom is that every call draws the same square. (2) They drag the `side_length`
block out of the function and into the main program, where it has no value; it only
means something inside the function that declares it. If a student deletes a
parameter later, any `side_length` block left in the body becomes a plain variable
that's never set — clean those out with them.

</TeacherNote>

## Parameter vs. argument

Two words that sound similar and trip everyone up:

- **Parameter** — the *name* in the definition: the `side_length` in
  `square (side_length)`. It's the empty slot.
- **Argument** — the *value* you pass in when you call it: the `50` in
  `square (side_length: 50)`. It's what fills the slot.

## Activity · Make your functions flexible

1. Add a `side_length` parameter to your `square` function — gear icon, then the
   Variables palette — and call it at three different sizes. If all three squares
   come out identical, you've done the first half and not the second: check what's
   actually sitting in the Straight block's *cm* slot.
2. Do the same for `triangle` — one function, any size triangle.
3. **Challenge:** add a *second* parameter, `effort`, and use it for the **Effort**
   on your Straight and Turn blocks: `square (side_length, effort)`. Then ask
   yourself whether it earns its keep — next lesson's polygon function takes
   `sides` and `side_length` only, and leaves Effort at `0.5`.

## Wrap-up

- What does a parameter let one function do? (Behave differently each time, based on the value you pass.)
- Parameter vs. argument? (Parameter = the name/slot; argument = the value you pass in.)
- Why does parameter order matter? (Arguments fill the slots in order.)

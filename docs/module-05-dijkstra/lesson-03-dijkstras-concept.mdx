This is the algorithm GPS systems use to find the shortest route — invented by Edsger
Dijkstra in 1956 and still in use today. You'll learn it the way you learned Manhattan:
**by hand, on paper**, before writing a line of code. Trace it a few times and the code in
Lessons 4–5 will feel like transcription.

<Objectives>

By the end of this lesson you will be able to:

- Name the three data structures: `distances`, `previous`, and `visited`
- Explain what each one stores
- Trace the algorithm step by step on a small grid
- Pick the correct next node (smallest distance, unvisited)
- Reconstruct the shortest path from `previous`

</Objectives>

## Part 1 · The three data structures

Dijkstra explores outward from the start, always visiting the nearest unvisited node next.
It keeps track of everything with three structures:

- **`distances`** — a dictionary of the shortest known distance from the start to each node. Start is `0`; everything else begins at "infinity" (we'll use a big number).
- **`previous`** — a dictionary of which node you came *from* to reach each node. Used to rebuild the path. Start's previous is `None`.
- **`visited`** — a list of nodes already finished. Once visited, a node's distance is final.

```
distances = {(0,0): 0}      # start is 0 steps from itself
previous  = {(0,0): None}    # nothing comes before the start
visited   = []               # nothing finished yet
```

## Part 2 · The algorithm in one sentence

> Repeat: pick the unvisited node with the **smallest** distance, update its neighbors,
> then mark it visited — until the destination is visited.

More precisely, each round:

1. Among unvisited nodes with a known distance, pick the one with the **smallest** distance — call it `current`.
2. For each unvisited **neighbor** of `current`: if going through `current` is shorter than the neighbor's current distance, update its distance and set its `previous` to `current`.
3. Mark `current` **visited**.

The key decision is step 1: you always visit the closest-to-*start* node next — **not** the one closest to the destination.

## Part 3 · Trace it: 3×3 with (1,1) blocked

Find the shortest path from (0,0) to (2,2), with (1,1) blocked:

```
(0,0) --- (0,1) --- (0,2)
  |                   |
(1,0)               (1,2)
  |                   |
(2,0) --- (2,1) --- (2,2)
```

| Step | Visit | Dist | Updates neighbors | visited grows to |
|---|---|---|---|---|
| 1 | (0,0) | 0 | (0,1)=1, (1,0)=1 | [(0,0)] |
| 2 | (0,1) | 1 | (0,2)=2 | …(0,1) |
| 3 | (1,0) | 1 | (2,0)=2 | …(1,0) |
| 4 | (0,2) | 2 | (1,2)=3 | …(0,2) |
| 5 | (2,0) | 2 | (2,1)=3 | …(2,0) |
| 6 | (1,2) | 3 | (2,2)=4 | …(1,2) |
| 7 | (2,1) | 3 | (2,2): 3+1 not < 4, no change | …(2,1) |
| 8 | (2,2) | 4 | destination visited — done | …(2,2) |

Notice (1,1) never appears — a blocked node simply isn't in the graph, so the algorithm
never touches it.

## Part 4 · Reconstruct the path

The `previous` dictionary rebuilds the route — trace **backward** from the destination:

```
previous: {(0,0): None, (0,1): (0,0), (0,2): (0,1),
           (1,0): (0,0), (1,2): (0,2), (2,0): (1,0),
           (2,1): (2,0), (2,2): (1,2)}

(2,2) ← (1,2) ← (0,2) ← (0,1) ← (0,0)   # (0,0)'s previous is None → stop
```

That gives `[(2,2), (1,2), (0,2), (0,1), (0,0)]` — backward. **Reverse it** for the real
path: `[(0,0), (0,1), (0,2), (1,2), (2,2)]`, 4 steps. It routed cleanly around (1,1).

Compared to Manhattan: on a *clear* grid, Dijkstra finds a path of the **same length**
as Manhattan (the exact route may differ). Its advantage isn't shorter paths — it's that
it **works with obstacles**.

## Wrap-up

- What are the three data structures and what does each hold? (`distances`, `previous`, `visited` — shortest distances, predecessors, and finished nodes.)
- How do you choose the next node? (Smallest known distance among unvisited.)
- Why reverse the reconstructed path? (You trace it backward from the destination.)

<TeacherNote title="The hardest lesson in the module — go slow, use the board">

Write the full state (distances / previous / visited) after *every* step; students must
see the structures change. Ask "which node next?" each round and make them answer before
you proceed — that's the core skill. The #1 confusion: they want to visit the node nearest
the *destination*; reinforce that it's smallest distance from the *start*. Emphasize that
blocked nodes simply aren't in the graph — the algorithm doesn't "skip" them, they're
absent. Path reconstruction feels backward; connect it to "how did you get here?" (you
hear the last step first). Save every completed trace — they're the test cases for Lessons
4 and 5.

</TeacherNote>

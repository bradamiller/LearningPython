## The mission

Four destinations, visited in order, starting and (optionally) ending at home base
(0,0). The two classes do the heavy lifting: `Manhattan.compute_path(dest)` returns the
list of intersections, and `Navigator.drive_path(path)` turns and drives it. Your job is
the **main program** that orchestrates them — about ten lines.

Write it yourself. The shape you need:

```python
# create one Manhattan and one Navigator, before the loop
# list your destinations in the order to visit them
# wait for the button
# for each destination:
#     compute the path
#     drive it
#     ... and make sure the planner knows where the robot ended up
#     print progress so you can follow along
```

That last comment is the one that decides whether the second leg works. Think
about what each object knows after `drive_path` finishes, and what it doesn't.

<TeacherNote title="Working main program (teacher copy)">

```python
HEADING_NAMES = ["N", "E", "S", "W"]

manhattan = Manhattan((0, 0))
navigator = Navigator((0, 0), 0)      # start heading North
destinations = [(2, 0), (2, 3), (0, 3), (0, 0)]

board.wait_for_button()

for dest in destinations:
    print("--- Navigating to", dest, "---")
    path = manhattan.compute_path(dest)
    print("Path:", path)
    navigator.drive_path(path)
    manhattan.position = navigator.position   # ← the key line
    print("Arrived at:", navigator.position)
```

`manhattan.position = navigator.position` is the line nearly everyone misses, and
the failure is instructive rather than obvious: leg one works perfectly, and every
later leg is computed from (0,0). If a student's robot drives a sensible first
route and then wanders, ask what `manhattan` thinks its position is.

</TeacherNote>

## Create objects once, reuse them

A common mistake is making new `Manhattan` and `Navigator` objects for every destination.
Don't — **create them once** before the loop and reuse them. That's the whole point of
classes: they hold state (position and heading) across many operations. And the
Navigator's heading **carries over** between legs: if it finished a leg facing East, it
starts the next one facing East. That's realistic, and it's why the turn math needs the
true current heading.

    {text: 'Random'},

  explanation="The Navigator keeps its state. It begins each leg facing however it finished the last — which is exactly why turn_to() must work from the real current heading."

## Activity · Test in three levels

Do **not** jump straight to the full run on the robot. If something breaks, you won't know
which piece. Build up:

1. **Manhattan alone (no robot).** Loop the destinations, print each path, set
   `manhattan.position = dest` between them. Confirm every path looks right on screen.
2. **One leg on the robot.** Place the robot at (0,0) facing North, run a single short
   destination. Correct turns? Arrives at the right cell?
3. **Full sequence.** Run all four. Watch the straight-through intersections and the turns.

```python
# Level 1 — desktop only
manhattan = Manhattan((0, 0))
for dest in [(2, 0), (2, 3), (0, 3), (0, 0)]:
    path = manhattan.compute_path(dest)
    print("To", dest, ":", path, " steps:", len(path))
    manhattan.position = dest
```

<TeacherNote title="Project day — short intro, incremental testing, and celebrate">

Keep the intro brief; this is a build-and-test day. The single most common bug is the

Push level-by-level testing hard; the students who write everything at once and can't find
the break are the ones who skipped Manhattan-only testing. Watch battery drain on long
multi-turn runs and charge between attempts. When a robot finishes the whole sequence, let
the class watch — it's the payoff of nine lessons. For 50-minute periods, plan two days:

## Real-world connections

The plan-then-execute structure you just built is fundamental to real autonomous systems:

<CardGrid>
  <InfoCard tag="Logistics" title="Delivery routing">
    Warehouse and delivery robots compute a route to each stop, drive it, then re-plan from the new location — exactly this loop.
  </InfoCard>
  <InfoCard tag="Rideshare" title="Multi-stop trips">
    Navigation apps chain legs together, recomputing from your current position at each waypoint.
  </InfoCard>
  <InfoCard tag="Space" title="Rover missions">
    Planetary rovers plan a path to a target, execute carefully, and re-plan — with the same separation of planning and driving.
  </InfoCard>
</CardGrid>

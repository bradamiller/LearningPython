## Heading is a number

Since Lesson 4-1 the program has carried a `robot_heading` that never changed. Now it gets
used. The four directions are numbered clockwise from North:

| Heading | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| Direction | North | East | South | West |

Numbers are easy to do arithmetic on (a clockwise quarter turn adds 1), but `0` in a
printout is hard to read, so the program also needs each heading's letter.

### Step 2 · Which way to face?

Between two *adjacent* intersections, either x changes by one **or** y changes by one,
never both. That's four cases:

| Coordinate change | Direction | Heading |
|---|---|---|
| y +1 (up, away from you) | North | 0 |
| x +1 (right) | East | 1 |
| y −1 (down, toward you) | South | 2 |
| x −1 (left) | West | 3 |

x comes first in the tuple, but North and South change the *second* number. **North is
away from you**, so moving North makes y *bigger*.

### Step 4 · Break it on purpose

In `drive_path()`, change `current_heading = turn_to(current_heading, desired_heading)` to
just `turn_to(current_heading, desired_heading)`. Predict what every `turning:` line will
start from, then run it.

<Reveal title="What happened?" hint="predict first">

Every one says `turning: from N`, and every `new position:` line says `heading: N`. It's
the dropped return from Lesson 4-1, one level down: `turn_to()` hands back the new heading,
and nobody caught it. On the floor, the robot would think it still faced North and turn
the wrong amount at every corner.

</Reveal>

Put `current_heading =` back and run it again.

<OptionalExtension title="Catching mistakes early" gate="Optional: open it if you have time. Nothing later depends on it.">

`get_desired_heading()` expects the next intersection to be **one step away**. What if
none of the four `if` lines is true? **When would that happen?** Think about it before
you open the answer.

<Reveal title="When would none of the four be true?" hint="make a guess first">

When `next_pos` is the same spot as `position`: nothing is bigger and nothing is smaller.
That only happens when there's a **bug in the planner**: a path that includes the start
(promise 1), so the first "move" goes nowhere.

</Reveal>

Without a check, `get_desired_heading()` reaches its end and quietly returns `None`. The
program then stops one line later, in `drive_path()`, with
`TypeError: list indices must be integers`: an error in the wrong place, about the wrong
thing. With a check, the program stops where the mistake was noticed and says which two
positions caused it:

```python
raise ValueError(str(next_pos) + " is not one step from " + str(position))
```

`raise` stops the program on the spot and prints your message. `ValueError` is Python's
name for "the values I was given make no sense". `str(position)` turns a tuple into text.

**Try it:** add step 3 to `get_desired_heading()`. Then add one more line at the *end* of
`test_headings()`:

```python
    get_desired_heading((1, 1), (1, 1))
```

Run it: the four answers print as before, then the program stops with your message.

This check catches a move that goes nowhere. A jump of two blocks, or a diagonal, still
gets a heading, because the four `if` lines only ask which number changed. The planner's
own tests are what rule those out.

</OptionalExtension>

<TeacherNote title="What to watch">

The grid orientation (x first in the tuple, but North is +y, away from you) is the #1
confusion; draw it, point at it, quiz it. The four `if` lines trust the planner's promise
that every step is to a neighbor, which `test_planner()` already checked.

The animation draws each turn the short way. The `turn_to()` stub just hands back the
heading it was asked for; how the robot really gets there is Lesson 4-5. Indexing and
`range(len(...))` are new here; Module 5 numbers the legs of a run with the same loop.
`raise` needs no more teaching than "the program stops and prints your message"; don't
detour into `try`/`except`.

</TeacherNote>

```python
# ===== NAVIGATOR =====
# Drives a planned path, one intersection at a time, and hands
# back where the robot ended up and which way it faces.
HEADING_NAMES = ["N", "E", "S", "W"]    # HEADING_NAMES[2] -> "S"

def get_desired_heading(position, next_pos):
    """Return the heading (0-3) that points from position to
    next_pos, which must be one step away."""
    x, y = position
    next_x, next_y = next_pos
    if next_y > y: return 0   # North
    if next_x > x: return 1   # East
    if next_y < y: return 2   # South
    if next_x < x: return 3   # West
    raise ValueError(str(next_pos) + " is not one step from " + str(position))

def test_headings():
    for next_pos in [(0, 1), (1, 2), (2, 1), (1, 0)]:
        heading = get_desired_heading((1, 1), next_pos)
        print("(1, 1) to", next_pos, ":", heading, HEADING_NAMES[heading])

def turn_to(current_heading, desired_heading):
    """STUB: pretend the robot turned. Lesson 4-5
    replaces it."""
    print("turning: from", HEADING_NAMES[current_heading],
          "to:", HEADING_NAMES[desired_heading])
    return desired_heading

def fake_track_to_intersection():
    """STUB for track_to_intersection(): print instead of
    driving. Lesson 4-6 swaps in the real one."""
    print("tracking to intersection")

def drive_path(path, current_position, current_heading):
    """Turn and drive through every intersection in path;
    return the final position and heading."""
    for next_pos in path:
        desired_heading = get_desired_heading(current_position, next_pos)
        print("moving: from", current_position, "to:", next_pos,
              "heading:", HEADING_NAMES[desired_heading])
        current_heading = turn_to(current_heading, desired_heading)
        fake_track_to_intersection()
        current_position = next_pos     # the robot is there now
    return current_position, current_heading

# --- The main program: the delivery run ---
DELIVERY_STOPS = [(2, 3), (1, 0), (3, 1), (2, 2), (0, 0)]

def test_delivery():
    robot_position = (0, 0)
    robot_heading = 0               # facing North
    for delivery_destination in DELIVERY_STOPS:
        path = compute_manhattan_path(robot_position, delivery_destination)
        print(path)
        robot_position, robot_heading = drive_path(
            path, robot_position, robot_heading)
        print("new position:", robot_position,
              "heading:", HEADING_NAMES[robot_heading])

# ===== RUN =====
board.wait_for_button()
test_delivery()
```

## Wrap-up

- What two steps happen at each intersection? (Turn to face the next one, then drive to it.)
- Between adjacent intersections, what can change? (x *or* y, by one: four cases, four headings.)
- What does `HEADING_NAMES[heading]` do? (Picks the item at that index, counting from 0: the heading's letter.)
- Why does `drive_path()` write `current_heading = turn_to(...)`? (`turn_to()` hands back the new heading; assigning it is the only way `drive_path()` keeps it.)

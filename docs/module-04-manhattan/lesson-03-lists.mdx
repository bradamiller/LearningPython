A tuple stores one position. A **path** is many positions in order — and for that you
need a **list**. By the end, you'll represent a route as a list of coordinate tuples
like `[(1,0), (2,0), (2,1), (2,2), (2,3)]`, and build one up step by step — exactly
what the Manhattan algorithm does next lesson.

That example is the route from `(0,0)` to `(2,3)`, and notice the robot's own
starting square isn't in it. A path lists the places the robot **drives to**; it's
already standing on the start, so putting it in the list would mean "drive to where
you already are." Every path in this module and the next works that way.

<Objectives>

By the end of this lesson you will be able to:

- Create a list with `[]` and see how it differs from a tuple
- Add items with `append()` and count them with `len()`
- Loop through a list with a `for` loop
- Build a list step by step inside a loop, and store a path as a list of tuples
- Explain what a variable holds when the value is a list, and what happens when two
  names refer to the same one

</Objectives>

## List vs. tuple

A **list** is an ordered collection written with square brackets — and unlike a tuple,
it's **mutable** (it can grow and change):

```python
numbers = [1, 2, 3, 4, 5]
print(numbers[0])     # 1   — indexing works like tuples
print(len(numbers))   # 5   — how many items
```

| | Tuple | List |
|---|---|---|
| Brackets | `( )` | `[ ]` |
| Can change? | No (immutable) | Yes (mutable) |
| Best for | a fixed position | a growing path |

So a *coordinate* is a tuple; a *path* is a list of tuples.

## Growing a list with `append()`

`append()` adds an item to the **end** of a list. Start empty and build up:

```python
path = []
path.append((1, 0))
path.append((2, 0))
path.append((3, 0))
print(path)        # [(1, 0), (2, 0), (3, 0)]
print(len(path))   # 3
```

That's a robot at `(0,0)` driving three squares down: three places to drive to, so
`len(path)` is 3 — the number of steps.

Loop through it with a `for` loop:

```python
for step in path:
    print("Visit:", step, " row:", step[0], " col:", step[1])
```

## Activity · Build a path in a loop

The pattern the whole module depends on: **start empty, append inside a loop.**

```python
path = []
for row in range(1, 5):          # start at 1, not 0 — the robot is already on row 0
    path.append((row, 0))
print(path)        # [(1, 0), (2, 0), (3, 0), (4, 0)]
```

`range(1, 5)` counts 1, 2, 3, 4 — it starts where you tell it to instead of at 0.
That's the whole trick to leaving the start out: the first square you append is the
first one the robot actually drives to.

Trace it and you'll see the list grow by one each pass. Change the loop to vary the
*column* instead, and you build a horizontal path. Combine a "go down" loop and a "go
right" loop and you've basically written the Manhattan algorithm.

<TeacherNote title="The build-in-a-loop pattern is make-or-break">

Spend real time on the build-in-a-loop activity and a trace table — Lesson 4-4's algorithm relies
*entirely* on "empty list, append inside a loop." If students don't own this pattern,
next lesson is brutal. **Demo the classic bug live:** put `append()` *outside* the
loop (wrong indentation) so only the last item lands, then fix the indentation. Keep
scope tight — they need `[]`, `append()`, `len()`, indexing, and `for`. No `insert`,
`pop`, slicing, or comprehensions yet.

</TeacherNote>

## What the variable actually holds

Back in Lesson 1-9, a variable was a named location in memory, and `=` stored a
value there. That's still true, and for a number it's the whole story:
`side_length = 30` puts a `30` in that location.

Remember the numbers on those locations — the **addresses**. Here is what they're
for.

A list can't be stored the way a number is, and the reason is physical. A list
grows: `append()` makes it longer. A memory location is a fixed size, so there is
no way to set aside one that's guaranteed big enough. Instead the list lives
somewhere else in memory, in as much room as it needs, and what goes in `path`'s
location is that area's **address** — the number that says where to find it. An
address stored in a variable is called a **reference**.

That sounds like a technicality until two names hold the same address:

```python
path = []
path.append((1, 0))

same_path = path          # copies the ADDRESS, not the list
same_path.append((2, 0))

print(path)               # [(1, 0), (2, 0)]  ← path changed too
```

`same_path = path` obeys exactly the rule you already know: work out the right
side, then store the result. The right side is what's *in* `path` — an address —
so that address is what gets stored in `same_path`. Nothing copied the list,
because the list was never in `path` to begin with.

<Figure
  src="/img/lesson-m4-03/two-names-one-list.svg"
  alt="The memory locations named path and same_path each hold the number 5120, and arrows run from both of them to one list stored at address 5120."
  caption="Two locations, the same address in each, one list at the end of both arrows."
/>

There is only **one list** here. `path` and `same_path` hold the same address, so
appending through either name changes the one list both of them lead to. If a list
were copied on assignment, `path` would still be one item long — it isn't.

Compare that with a number, which is small and fixed in size, so it really is
stored in the location itself:

```python
a = 5
b = a                     # copies the VALUE
b = b + 1
print(a)                  # 5  ← unchanged
```

  question="After  scores = [10, 20]  /  backup = scores  /  backup.append(30)  what does scores hold?"
  options={[
    {text: '[10, 20]  — backup is a separate copy'},
    {text: '[10, 20, 30]  — both names refer to the same list', correct: true},
    {text: '[30]'},
    {text: 'An error — you cannot assign a list to another name'},
  ]}
  explanation="backup = scores stores the address that was in scores, not a copy of the list, so both names lead to one list. Appending through either name changes what both see. To get an independent copy you would have to make a new list."
/>

This is not a trap to avoid — it's the mechanism the rest of the course relies on.
In Module 5 you'll build a list of blocked intersections, hand it to a planner
object, and keep adding to it as the robot discovers obstacles. The planner sees
every new obstacle precisely *because* it holds the address of your list rather
than a frozen copy of it.

<TeacherNote title="Nothing from Lesson 1-9 gets taken back here">

Worth being explicit with students, because it's the difference between a model
they trust and one they suspect: this section **adds** to Lesson 1-9, it doesn't
correct it. A variable is still a named memory location, and `=` still works out
the right side and stores the result there. Every one of those sentences is as
true on this page as it was in Module 1. The only new fact is what the stored
value *is* for a list — the address that was printed on the location all along.

If a student asks why the address exists at all, the physical reason is the honest
one and they can hold it: a location is a fixed size, a list can grow, so the list
has to live somewhere with room to grow and the location keeps the number that
says where.

The demo that lands: two students each hold a slip of paper with the same post
office box number on it. One of them goes and puts something in the box. The other
one's slip hasn't changed — it's the same number it always was — but what they find
when they open the box has. Then ask what would have to be different for them to
have *separate* boxes.

Don't teach `copy()` or slicing yet — nothing in this course needs an independent
copy, and the aliasing is load-bearing in Module 5.

</TeacherNote>

## The most common list bug

Indentation decides what's inside the loop. Get it wrong and only the last item is
added:

```python
# WRONG — append is outside the loop
path = []
for row in range(1, 4):
    position = (row, 0)
path.append(position)     # only runs once → [(3, 0)]

# CORRECT — append is inside the loop
path = []
for row in range(1, 4):
    position = (row, 0)
    path.append(position)  # runs each pass → [(1, 0), (2, 0), (3, 0)]
```

  question="A student's loop ends with a list holding only the LAST coordinate instead of all of them. What's wrong?"

## Wrap-up

- Tuple vs list — which is for a position, which for a path? (Tuple = position; list = path.)
- What does `append()` do? (Adds an item to the end.)
- What's the pattern for building a path? (Start with `[]`, `append()` inside a loop.)
- If two names refer to the same list and you append through one, what does the other see? (The change — there's only one list, and both names hold its address.)

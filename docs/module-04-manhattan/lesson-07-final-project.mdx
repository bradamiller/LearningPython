## The mission

Four destinations, visited in order, starting and ending at home base (0,0). The two halves do the heavy lifting: `compute_manhattan_path(position, dest)`
returns the list of intersections, and `drive_path(path, position, heading)` drives it
and hands back the new pose. Your job is the **main program** that connects them — about ten lines, and
like every program in this course it is a test function at the bottom of `robot.py`.

<TeacherNote title="Solution (teacher copy)">

This lesson's addition to the NAVIGATOR section of `robot.py`, plus the run block; the
rest of the file is as the Lesson 4-6 teacher copy left it. The whole file is
in the [Module 4 sample programs](/teacher-guide/sample-programs/module-4). `test_delivery()` is the
graded work, and there is no student reveal for any of the three tests.

```python
# --- Lesson 4-7: final project, the delivery run ---
# The module project: visit DESTINATIONS in order, planning
# each leg with the MANHATTAN PLANNER from wherever the last
# leg ended and driving it with the NAVIGATOR. Nothing new is
# defined; the two sections did the work. Built in three
# tested steps: one leg, two legs, then a loop.
DESTINATIONS = [(2, 0), (2, 3), (0, 3), (0, 0)]

def test_one_leg():
    position = (0, 0)
    heading = 0                   # start facing North
    path = compute_manhattan_path(position, (2, 0))
    print("Path:", path)
    board.wait_for_button()
    position, heading = drive_path(path, position, heading)
    print("Arrived at:", position, "facing", HEADING_NAMES[heading])

def test_two_legs():
    position = (0, 0)
    heading = 0
    path = compute_manhattan_path(position, (2, 0))
    print("Path:", path)
    board.wait_for_button()
    position, heading = drive_path(path, position, heading)
    print("Arrived at:", position, "facing", HEADING_NAMES[heading])

    path = compute_manhattan_path(position, (2, 3))
    print("Path:", path)
    position, heading = drive_path(path, position, heading)
    print("Arrived at:", position, "facing", HEADING_NAMES[heading])

def test_delivery():
    position = (0, 0)
    heading = 0                   # start facing North

    print("Planned path for leg 1:",
          compute_manhattan_path(position, DESTINATIONS[0]))
    board.wait_for_button()

    for dest in DESTINATIONS:
        print("--- Navigating to", dest, "---")
        path = compute_manhattan_path(position, dest)
        print("Path:", path)
        position, heading = drive_path(path, position, heading)   # <- the key line
        print("Arrived at:", position, "facing", HEADING_NAMES[heading])

# ===== RUN =====
board.wait_for_button()
test_delivery()
```

The marked line is the one nearly everyone gets half right: they call `drive_path` and throw the
return value away. The failure is instructive rather than obvious — leg one works
perfectly, and every later leg is planned from (0,0) facing North. If a student's robot
drives a sensible first route and then wanders, ask what `position` is in their main
program after leg 1.

**Class track:** `test_delivery()` is handed `navigator.position` by the planner call,
drives with `navigator.drive_path(path)`, and prints `navigator.position` — there is no
`position, heading = ...` line to get half right. With the `Manhattan` class the
planner call is `planner.compute_path(...)`.

</TeacherNote>

## Only the first leg is printed before the button

Lesson 4-6's habit — plan, print, button, drive — appears here with one limit. The main
program prints the path for leg 1 before the button. It can't print legs 2, 3 and 4 yet,
because each of them is planned from wherever the previous leg actually finished.
Instead, each leg is printed as it's planned, just before the robot drives it. (In
Module 5, where obstacles can appear mid-run, this becomes the only way it *could* work.)

The heading carries over the same way: if leg 1 ends facing East, leg 2 starts facing
East. That's why `turn_to()` works from the robot's real heading, not North.

## Activity · Build it in three steps

Test each step on the robot before you write the next. Start the robot at (0, 0) facing
North every time.

### Step 1 · One leg

Write `test_one_leg()` and set the run line to it. It is Lesson 4-6's
`test_drive_path()` with (2, 0) as the destination. Read the printed path,
`[(1, 0), (2, 0)]`, then press again. The robot should make one right turn and stop on
(2, 0) facing East.

### Step 2 · Two legs, one after the other

Write `test_two_legs()` and run it. The second leg is planned from where the first
ended, so it works only if `position` and `heading` were assigned from the first
`drive_path()`. After (2, 0), the robot should make three right turns to face North and
drive up to (2, 3).

### Step 3 · A list and a loop

Write `test_delivery()`: the legs become one loop over `DESTINATIONS`. Run it. The robot
should visit all four destinations and finish at home, with legs of 2, 3, 2 and 3
steps.

## Real-world connections

The plan-then-execute structure you just built is fundamental to real autonomous systems:

<CardGrid>
  <InfoCard tag="Logistics" title="Delivery routing">
    Warehouse and delivery robots compute a route to each stop, drive it, then re-plan from the new location — exactly this loop.
  </InfoCard>
  <InfoCard tag="Rideshare" title="Multi-stop trips">
    Navigation apps chain legs together, recomputing from your current position at each waypoint.
  </InfoCard>
  <InfoCard tag="Space" title="Rover missions">
    Planetary rovers plan a path to a target, execute carefully, and re-plan — with the same separation of planning and driving.
  </InfoCard>
</CardGrid>

## Wrap-up

- What's the one line that makes multi-leg journeys work? For each leg:

  ```python
  position, heading = drive_path(path, position, heading)
  ```
- Why is only leg 1 printed before the button? (Later legs are planned from where the robot actually ends up.)
- What were the three steps? (One leg, two legs, then a loop over a list.)
- Where did problem decomposition pay off? (Each part was built and tested alone, so the main program that connects them is about ten lines, and a printed path tells you which part to open when a run goes wrong.)

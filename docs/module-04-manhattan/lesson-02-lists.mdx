A tuple stores one position. A **path** is many positions in order — and for that you
need a **list**. By the end, you'll represent a route as a list of coordinate tuples
like `[(1,0), (2,0), (2,1), (2,2), (2,3)]`, and build one up step by step — exactly
what the Manhattan algorithm does next lesson.

Try this lesson's code in a new file, not `robot.py`.

That example is the route from `(0,0)` to `(2,3)`, and notice the robot's own
starting intersection isn't in it. A path lists the places the robot **drives to**; it's
already standing on the start, so putting it in the list would mean "drive to where
you already are." Every path in this module and the next works that way.

## List vs. tuple

A **list** is an ordered collection written with square brackets — and unlike a tuple,
it's **mutable** (it can grow and change):

```python
numbers = [1, 2, 3, 4, 5]
print(numbers[0])     # 1   -- indexing works like tuples
print(len(numbers))   # 5   -- how many items
```

| | Tuple | List |
|---|---|---|
| Brackets | `( )` | `[ ]` |
| Can change? | No (immutable) | Yes (mutable) |
| Best for | a fixed position | a growing path |

So a *coordinate* is a tuple; a *path* is a list of tuples.

## Growing a list with `append()`

`append()` adds an item to the **end** of a list. Start empty and build up:

```python
path = []
path.append((1, 0))
path.append((2, 0))
path.append((3, 0))
print(path)        # [(1, 0), (2, 0), (3, 0)]
print(len(path))   # 3
```

That's a robot at `(0,0)` driving three intersections to the right: three places to drive to, so
`len(path)` is 3 — the number of steps.

To visit every step, you could count through the indexes with `range()` and look each
one up:

```python
for i in range(len(path)):
    step = path[i]
    print("Visit:", step, " x:", step[0], " y:", step[1])
```

That's so common that Python has a shortcut. In `for step in path:`, each element of the
list is assigned in turn, first to last, to the variable on the left of `in`. No index
needed:

```python
for step in path:
    print("Visit:", step, " x:", step[0], " y:", step[1])
```

Both loops print the same three lines.

## Activity · Build a path in a loop

The pattern the whole module depends on: **start empty, append inside a loop.**

```python
path = []
for x in range(1, 4):            # start at 1, not 0 -- the robot is already at x = 0
    path.append((x, 0))
print(path)        # [(1, 0), (2, 0), (3, 0)]
```

`range(1, 4)` counts 1, 2, 3 — it starts where you tell it to instead of at 0.
That's the whole trick to leaving the start out: the first intersection you append is the
first one the robot actually drives to.

Trace it and you'll see the list grow by one each pass. Change the loop to vary
*y* instead, and you build a vertical path. Combine a "go right" loop and a "go
up" loop and you've basically written the Manhattan algorithm.

## What the variable actually holds

In Lesson 1-9, a variable was a named location in memory, and `=` stored a value
there. For a number, that's the whole story.

A list grows, but a memory location is a fixed size. So the list lives somewhere else
in memory, and the variable holds its **address**. An address stored in a variable is
called a **reference**. It matters when two variables hold the same address:

```python
a = 5
b = a                     # copies the VALUE: two 5s

path = [(1, 0)]
same_path = path          # copies the ADDRESS: still one list
same_path.append((2, 0))
print(path)               # [(1, 0), (2, 0)]  <- path changed too
```

This isn't a trap; the course relies on it. In Module 5 a planner sees each obstacle
you add to your list because it holds the list's address, not a copy.

<TeacherNote title="Nothing from Lesson 1-9 gets taken back here">

Worth being explicit with students, because it's the difference between a model
they trust and one they suspect: this section **adds** to Lesson 1-9, it doesn't
correct it. A variable is still a named memory location, and `=` still works out
the right side and stores the result there. Every one of those sentences is as
true on this page as it was in Module 1. The only new fact is what the stored
value *is* for a list — the address that was printed on the location all along.

If a student asks why the address exists at all, the physical reason is the honest
one and they can hold it: a location is a fixed size, a list can grow, so the list
has to live somewhere with room to grow and the location keeps the number that
says where.

The demo that lands: two students each hold a slip of paper with the same post
office box number on it. One of them goes and puts something in the box. The other
one's slip hasn't changed — it's the same number it always was — but what they find
when they open the box has. Then ask what would have to be different for them to
have *separate* boxes.

Don't teach `copy()` or slicing yet — nothing in this course needs an independent
copy, and the aliasing is load-bearing in Module 5.

</TeacherNote>

## The most common list bug

Indentation decides what's inside the loop. Get it wrong and only the last item is
added:

```python
# WRONG -- append is outside the loop
path = []
for x in range(1, 4):
    position = (x, 0)
path.append(position)     # only runs once -> [(3, 0)]

# CORRECT -- append is inside the loop
path = []
for x in range(1, 4):
    position = (x, 0)
    path.append(position)  # runs each pass -> [(1, 0), (2, 0), (3, 0)]
```

## Wrap-up

- Tuple vs list — which is for a position, which for a path? (Tuple = position; list = path.)
- What does `append()` do? (Adds an item to the end.)
- What's the pattern for building a path? (Start with `[]`, `append()` inside a loop.)
- If two variables refer to the same list and you append through one, what does the other see? (The change — there's only one list, and both variables hold its address.)

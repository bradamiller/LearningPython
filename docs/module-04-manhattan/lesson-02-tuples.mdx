## One value, two numbers

You *could* store a position in two variables — `x = 2`, `y = 3` — but that gets
messy fast (ten positions would need twenty variables). A **tuple** packs both into
one value, written with parentheses:

```python
position = (2, 3)
start = (0, 0)
destination = (3, 2)
```

Pull the pieces out by **index** — and since Python counts from zero (just like our
grid), index `0` is x and index `1` is y:

```python
position = (2, 3)
print(position[0])   # 2  -> x, across
print(position[1])   # 3  -> y, away from you
```

## Unpacking: both numbers at once

Indexing pulls out one part at a time. Often you want both, as ordinary variables, and
Python has a one-line way to get them:

```python
position = (2, 3)
x, y = position      # x is 2, y is 3
```

That's **tuple unpacking**. Python takes the names on the left in order and gives each
one the matching part of the tuple: the first name gets index 0, and the second gets
index 1. It does exactly what these two lines do:

```python
x = position[0]
y = position[1]
```

The names are yours to choose (`dest_x, dest_y = destination` works the same way), but
there must be exactly as many names as parts. Two names and a three-part tuple, or three
names and a two-part tuple, and Python stops with a `ValueError`.

You'll use this constantly from here on. Lesson 4-4's planner starts by unpacking where
the robot is and where it's going, so its loops can compare plain numbers.

## Tuples don't change (and that's good)

Try to modify a tuple and Python stops you:

```python
position = (2, 3)
position[0] = 5      # TypeError: 'tuple' object does not support item assignment
```

Tuples are **immutable** — once made, they can't be altered. That's exactly right for
a coordinate: `(2, 3)` should *always* mean x = 2, y = 3. To represent a new spot,
you make a new tuple:

```python
old_position = (2, 3)
new_position = (3, 3)    # one step east -- a brand-new tuple
```

Think of a street address: it doesn't change. Move, and you get a *new* address — you
don't edit the old one.

## Comparing positions

`==` checks whether two tuples are the *same* position — both parts must match, in
order:

```python
current = (1, 2)
target  = (1, 2)
print(current == target)   # True

other = (2, 1)
print(current == other)    # False -- order matters!
```

This matters later: the algorithm asks "have we reached the destination yet?" by
comparing tuples.

## Activity · Manhattan distance in code

The paper counting from Lesson 4-1 becomes simple arithmetic on tuple parts:

```python
start = (0, 0)
destination = (2, 3)

x_distance = destination[0] - start[0]     # 2
y_distance = destination[1] - start[1]     # 3
total_steps = x_distance + y_distance      # 5
print("Total steps:", total_steps)
```

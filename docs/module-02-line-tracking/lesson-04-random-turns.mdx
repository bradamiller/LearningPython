Your bounce robot has a flaw: turning exactly 180° every time, it just retraces the
same path back and forth and never explores the rest of the circle. The fix is
**randomness** — turning a different amount each bounce. To get it, you'll `import`
one of Python's built-in toolboxes.

## Modules and `import`

Python ships with thousands of ready-made tools grouped into **modules** — think of
each as a toolbox. To use one, you `import` it at the top of your file. You've done
this already for the robot (`from XRPLib.reflectance import Reflectance`); for random
numbers you import Python's built-in `random`:

```python
import random

for i in range(5):
    number = random.randint(1, 10)
    print("Random number:", number)
```

`random.randint(1, 10)` hands back **one** random whole number from 1 to 10,
*including* both ends. Run it again and you'll (usually) get a different number.

## Random bounce driving

The only change from Lesson 2-3 is swapping the fixed `turn(180)` for a random angle:

```python
from XRPLib.reflectance import Reflectance
from XRPLib.differential_drive import DifferentialDrive
from XRPLib.board import Board
import random

reflectance = Reflectance.get_default_reflectance()
drivetrain = DifferentialDrive.get_default_differential_drive()
board = Board.get_default_board()

threshold = 0.5

board.wait_for_button()

while True:
    left = reflectance.get_left()
    right = reflectance.get_right()

    if left > threshold or right > threshold:
        drivetrain.stop()
        angle = random.randint(90, 270)          # a different turn each time
        print("Line detected! Turning", angle, "degrees")
        drivetrain.turn(angle)
    else:
        drivetrain.set_effort(0.3, 0.3)
```

Now each bounce picks a fresh angle between 90° and 270°, so the robot fans out and
covers the whole circle instead of pacing the same line.

<TeacherNote title="Why 90–270, not 0–360?">

The range matters. `randint(90, 270)` guarantees the robot meaningfully changes
direction. A range that includes very small angles (or 0) can send it straight back
across the line it just hit, or barely turn at all — so it drifts out of the circle.
Have students experiment (Lesson worksheet has a range table) and *see* why a
mid-range band explores best. Good moment to note computer randomness is really
"pseudo-random" — deterministic underneath, but plenty random for us.

</TeacherNote>

## Activity · Experiment

1. Add `import random` and the random angle to your Lesson 2-3 program.
2. Try three different ranges — `randint(170, 190)`, `randint(90, 270)` and
   `randint(45, 315)` — and write down, for each, how the robot's coverage of the
   circle changes. Which one explores best, and why?
3. **Challenge:** randomize the *speed* too — `speed = random.randint(20, 50) / 100`
   gives an effort from 0.2 to 0.5.

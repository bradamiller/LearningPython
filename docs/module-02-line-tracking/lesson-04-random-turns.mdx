Your bounce robot has a flaw: turning exactly 180° every time, it just retraces the
same path back and forth and never explores the rest of the circle. The fix is
**randomness** — turning a different amount each bounce. To get it, you'll `import`
one of Python's built-in toolboxes.

## Modules and `import`

Python ships with thousands of ready-made tools grouped into **modules** — think of
each as a toolbox. To use one, you `import` it at the top of your file. You've done
this already for the robot:

```python
from XRPLib.reflectance import Reflectance
```

For random numbers you import Python's built-in `random`:

```python
import random

for i in range(5):
    number = random.randint(1, 10)
    print("Random number:", number)
```

`random.randint(1, 10)` hands back **one** random whole number from 1 to 10,
*including* both ends. Run it again and you'll (usually) get a different number.

## Random bounce driving

The only change from Lesson 2-3 is in the `if` branch: instead of a fixed
`turn(180)`, pick a random angle first and turn by *that*. Nothing else in the
program moves. In outline:

```python
import random          # at the top of robot.py, with the other imports

def test_random_bounce():
    # a copy of test_bounce(), with the if branch becoming:
    #     stop
    #     pick a random whole number of degrees, 90 to 270
    #     print it, so you can see each choice
    #     turn by that many degrees
    pass
```

Paste the new test above `RUN` and keep `test_bounce()` as it is — by the end of the
module your file is a record of everything the robot has learned to do, and the
fixed-angle bounce is part of that.

Each bounce now picks a fresh angle between 90° and 270°, so the robot fans out and
covers the whole circle instead of pacing the same line. Why that range and not 0 to
360? Because the robot has to *meaningfully* change direction: an angle near 0 barely
turns it, and it drifts out of the circle; an angle near 180 sends it straight back
the way it came. The band in the middle is where exploring happens.

  options={[

    {text: 'The robot retraces the same path back and forth and never explores the rest', correct: true},
    {text: '180° turns are inaccurate on hardware'},

  explanation="A 180° turn sends the robot straight back the way it came, so it bounces between the same two points forever. Random angles break that."

<TeacherNote title="Why 90–270, not 0–360?">

The range matters. `randint(90, 270)` guarantees the robot meaningfully changes
direction. A range that includes very small angles (or 0) can send it straight back
across the line it just hit, or barely turn at all — so it drifts out of the circle.
Have students experiment (Lesson worksheet has a range table) and *see* why a
mid-range band explores best. Good moment to note computer randomness is really
"pseudo-random" — deterministic underneath, but plenty random for us.

</TeacherNote>

### Step 1 · The random turn

Add `import random` at the top of `robot.py`, copy the body of `test_bounce()` into
`test_random_bounce()`, and change the `if` branch as outlined. Set the run line to
`test_random_bounce()` and run it: the printed angle should be different on (almost)
every bounce, and the robot should wander the whole circle instead of pacing one line.

### Step 2 · Try three ranges

Try `randint(170, 190)`, `randint(90, 270)` and `randint(45, 315)`, and write down,
for each, how the robot's coverage of the circle changes. Which one explores best,
and why?

### Step 3 · Challenge — random speed too

`randint()` only gives whole numbers, and `set_effort()` wants a value between 0 and
1. Pick a whole number in a range you choose, divide it to get an effort between
0.2 and 0.5, and drive at that speed until the next bounce.

<Reveal title="Check your test" hint="run yours on the robot first">

```python
def test_random_bounce():
    while True:
        if is_either_on_line():
            drivetrain.stop()
            angle = random.randint(90, 270)      # a different turn each time
            print("Line detected! Turning", angle, "degrees")
            drivetrain.turn(angle)
        else:
            drivetrain.set_effort(0.3, 0.3)
```

</Reveal>

<TeacherNote title="Solution (teacher copy)">

The addition to `robot.py` this lesson, with the step 3 challenge; the rest of the
file is as the Lesson 2-3 teacher copy left it, plus `import random` at the top. The
file is `lesson-04-random-turns.py` in the Module 2 solutions. Step 3 is hand-in
work; the step 1 test is behind the student reveal above. The division trick in step
3 (`randint(20, 50) / 100`) is the part students have to find; most try
`randint(0.2, 0.5)` first and get an error.

```python
def test_random_bounce():
    speed = 0.3
    while True:
        if is_either_on_line():
            drivetrain.stop()
            angle = random.randint(90, 270)
            speed = random.randint(20, 50) / 100
            print("Turning", angle, "degrees, then speed", speed)
            drivetrain.turn(angle)
        else:
            drivetrain.set_effort(speed, speed)

# ===== RUN =====
board.wait_for_button()
test_random_bounce()
```

</TeacherNote>

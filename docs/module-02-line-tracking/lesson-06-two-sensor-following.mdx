Last lesson the robot followed one *edge* with a single sensor. Now you'll use
**both** sensors together — and the code actually gets simpler. The robot straddles
the line and follows its **center**, giving smoother, more reliable tracking.

<Objectives>

By the end of this lesson you will be able to:

- Explain why two sensors track better than one
- Compute error with two sensors: `error = left − right`
- Predict the sign of the error from the robot's position
- Build a two-sensor proportional control loop
- Explain the negative sign in `arcade(base_effort, -correction)`

</Objectives>

## Part 1 · The difference *is* the error

With two sensors straddling the line, you don't need a setpoint anymore. Just
subtract one reading from the other:

> error = left − right

When both sensors read the same, the difference is zero and the robot drives
straight. When one drifts onto the line, the difference tells you exactly how much
and which way:

| Position | left | right | error = L − R | Meaning |
|---|---|---|---|---|
| Centered | 0.5 | 0.5 | `0.0` | drive straight |
| Drifted left | 0.8 | 0.2 | `+0.6` | steer left to correct |
| Drifted right | 0.2 | 0.8 | `−0.6` | steer right to correct |
| Both on white | 0.1 | 0.1 | `0.0` | straight (lost line) |
| Both on black | 0.9 | 0.9 | `0.0` | straight (an intersection!) |

## Part 2 · The control loop (and that negative sign)

The loop is the same rhythm as Lesson 5 — read, compute, steer — just with the new
error and a **negated** correction:

```python
from XRPLib.differential_drive import DifferentialDrive
from XRPLib.reflectance import Reflectance
from XRPLib.board import Board
import time

drivetrain = DifferentialDrive.get_default_differential_drive()
reflectance = Reflectance.get_default_reflectance()
board = Board.get_default_board()

Kp = 0.5            # tune this
base_effort = 0.3

board.wait_for_button()

while True:
    left_sensor = reflectance.get_left()
    right_sensor = reflectance.get_right()

    error = left_sensor - right_sensor
    correction = error * Kp
    drivetrain.arcade(base_effort, -correction)   # note the minus sign

    time.sleep(0.01)
```

Why the minus? A **positive** error means the robot drifted **left**, so it must
steer left — and in `arcade()` a *negative* turn steers left. Negating the
correction lines the math up with reality.

<KnowledgeCheck
  question="Why is the correction negated in arcade(base_effort, -correction) here, when Lesson 5 didn't negate it?"
  options={[
    {text: 'The meaning of a positive error flipped, so the steer direction has to flip too', correct: true},
    {text: 'Two sensors always need a negative sign no matter what'},
    {text: 'It makes the robot go faster'},
    {text: 'It fixes a bug in arcade()'},
  ]}
  explanation="With two sensors, a positive error means 'drifted left → steer left', which is a negative turn in arcade — so we negate the correction."
/>

<TeacherNote title="Teach the sign with the explorer program first">

Before the control loop, run a read-and-print program and have students **manually
slide the robot across the line**, watching `error = left − right` go positive,
negative, and zero in real time. That physical intuition makes the negative sign
click. Spend real time on *why* the sign flipped from Lesson 5 (the meaning of a
positive error changed) — it's the subtle point of the lesson. Expect to re-tune
`Kp`, since the error range differs from the one-sensor version.

</TeacherNote>

## Wrap-up

- What's the two-sensor error formula, and why no setpoint? (`left − right`; equal readings already mean zero.)
- Positive error means the robot drifted which way? (Left.)
- Why the negative sign on the correction? (A positive error needs a left steer, which is a negative turn in `arcade()`.)

## The mission

Your robot must:

1. Follow the taped circle with `track_to_intersection()`.
2. Detect the cross intersection.
3. Reverse direction.
4. Keep following, and repeat for **4 total reversals**.
5. Stop and print a completion message.

## Build it in pieces

You have every part already: the LINE SENSOR section finished in Lesson 2-7, the LINE
TRACKING section finished in Lesson 2-9, and the reversal trick you worked out above.
What's left is assembling them and tuning — which is most of what real robot work is.

Build in this order, and don't go on until each step works:

1. **Park on the cross.** Set the run line to `test_park()` from Lesson 2-9 and run it
   once more. Does the robot stop with its *wheels* on the cross?
2. **One turn.** Set the run line to `test_turn()`. Does the turn find the line again?
3. **One full reversal.** Write the body of `test_reversal()` and run it: park, two
   clockwise turns, follow back the other way to the same cross. (If you did the Lesson
   2-9 challenge, `test_turn_around()` is this test already.)
4. **The loop.** Write `test_final_project()` under your plan comments and set the run
   line to it.

<TeacherNote title="Solution (teacher copy)">

This lesson's addition to the LINE TRACKING section of `robot.py`, plus the run block;
the rest of the file is as the Lesson 2-9 teacher copy left it. Two clockwise
sensor-ended turns make a 180° reversal on the line. Use it to unstick a team, not as
a handout — the assembly and tuning is the graded work, and there is no student
reveal for it. The file is `lesson-10-final-project.py` in the Module 2 solutions; the
class version is `lesson-10-final-project-class-addon.py` (same two tests with
`tracker.` in front of every driving call).

```python
# --- Lesson 2-10: final project ---
# The module project: lap the circle, reversing at the cross,
# four times, then stop. Nothing new is defined for it. It is
# a list of calls to the four driving functions above, which
# is the point: the sections did the work, the project
# assembles them.

def test_reversal():
    track_to_intersection()
    drive_past_intersection()
    turn_clockwise()
    turn_clockwise()      # two sensor-ended turns = 180 deg
    track_to_intersection()
    print("Done!")

def test_final_project():
    print("Module 2 Final Project -- starting!")
    for leg in range(4):
        # follow the line to the cross
        print("Leg", leg + 1, "-- following to the cross...")
        track_to_intersection()
        # park the wheels on the cross
        drive_past_intersection()
        # turn around: two sensor-ended turns
        print("Cross detected! Reversing...")
        turn_clockwise()
        turn_clockwise()
    print("Done! 4 reversals complete.")

# ===== RUN =====
board.wait_for_button()
test_final_project()
```

</TeacherNote>

<TeacherNote title="Run it as a build, and test in pieces">

Treat this as a multi-day arc: plan → build → test → present. Insist on **incremental
testing** — `test_park()`, then `test_turn()`, then `test_reversal()`, then the
four-rep loop. The common fixes are all *tuning*: `THRESHOLD` (cross not detected),
the blind part of the turn or `TURN_EFFORT` (the loop ends on the old line, or spins
past the new one), and `BASE_EFFORT` (overshoots the cross) — frame that tuning as the
real engineering, not failure. Two successful reversals already demonstrate mastery;
four is the goal.

</TeacherNote>

## Activity · Test, tune, present

Work up in stages, and keep a note of what you tuned:

1. Does `test_park()` follow and stop at the cross, with the wheels left on it?
2. Does one turn in `test_turn()` find the line again?
3. Does `test_reversal()` work end to end?
4. Do all four reversals in `test_final_project()` run and stop?

Then demo it and reflect: what was hardest, how did building the file one tested
function at a time make the project easier, and what would you add with more time?

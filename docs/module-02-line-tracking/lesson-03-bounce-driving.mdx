Stopping at the line is fine — but what if the robot should keep going, bouncing off
each edge like a ball in a box? To do that, the robot has to make a **decision** every
moment: *if* I see the line, turn around; *otherwise*, keep driving. That's the
`if/else` statement.

- Combine `while True`, `if/else`, and a sensor read for continuous decisions
- Use the logical operators `and`, `or`, and `not`
- Write the bounce program from a pseudocode outline and the setup code

</Objectives>

## Making a decision with `if/else`

An `if/else` runs one block when a condition is true and a different block when it's
false — never both:

```python
if condition:
    # runs when the condition is True
else:
    # runs when the condition is False
```

A non-robot example makes the shape clear:

```python
temperature = 85
if temperature > 80:
    print("It's hot outside!")
else:
    print("It's comfortable.")
```

## The bounce algorithm

The behavior in plain English:

```text
loop forever:
    read the sensor
    if the sensor sees the line:
        stop, then turn around
    else:
        keep driving forward
```

"Loop forever" is `while True:` — a loop whose condition is always true, so it runs
until you power the robot off. That's completely normal in robotics; real robots run
a loop like this the whole time they're on.

<TeacherNote title="while True is normal — and safe to stop">

Students sometimes think `while True` will "crash" the program — reassure them it's
the standard control-loop pattern, and the way to stop it is the robot's stop button
or power. Also note `drivetrain.stop()` before `turn(180)` just makes for a cleaner
pivot. On real hardware the 180° won't be exact — that's expected, and Lesson 2-4
turns it into a feature.

</TeacherNote>

## Combining conditions

One sensor can miss the line if the robot hits it at an angle. Checking **both** is
safer — and that's where `or` comes in: it's true if *either* side is true, so
`left > threshold or right > threshold` means *at least one sensor sees the line*.

The three logical operators: `and` (both must be true — you used it in Lesson 2-2),
`or` (at least one true), `not` (flips true/false).

## Activity · Build the bounce

As in Lesson 2-2, the setup is given and the loop is yours. The pseudocode above is
the plan; every line of it is something you can already write.

```python
from XRPLib.reflectance import Reflectance
from XRPLib.differential_drive import DifferentialDrive
from XRPLib.board import Board

reflectance = Reflectance.get_default_reflectance()
drivetrain = DifferentialDrive.get_default_differential_drive()
board = Board.get_default_board()

threshold = 0.5   # YOUR value from Lesson 2-1

board.wait_for_button()

# loop forever:
#     read the left sensor
#     if it sees the line:
#         stop, print a message, turn around
#     else:
#         drive forward
```

### Step 1 · One sensor

Turn the comments into code. Start the robot inside the circle, press the button, and
watch it bounce back and forth. If it drives through the line, check which way your
comparison points — the sensor reads *high* on the line.

### Step 2 · Either sensor

Read the right sensor too, and change the condition so the robot bounces when
*either* sensor sees the line.

### Step 3 · Challenge — count the bounces

Add a `bounce_count` variable that goes up by one each bounce, and print it. You'll
build on counters like this later.

<Reveal title="Check your loop" hint="run yours on the robot first">

Step 1:

```python
while True:
    left = reflectance.get_left()

    if left > threshold:
        drivetrain.stop()
        print("Line detected! Turning around...")
        drivetrain.turn(180)
    else:
        drivetrain.set_effort(0.3, 0.3)
```

Step 2 changes the condition to `left > threshold or right > threshold`, with a
second read for `right` above it.

</Reveal>

<TeacherNote title="Solution (teacher copy)">

The complete program with steps 2 and 3, as `lesson-03-bounce-driving.py` in the
Module 2 solutions. Step 3 is hand-in work; the step 1 loop is behind the student
reveal above.

```python
from XRPLib.reflectance import Reflectance
from XRPLib.differential_drive import DifferentialDrive
from XRPLib.board import Board

reflectance = Reflectance.get_default_reflectance()
drivetrain = DifferentialDrive.get_default_differential_drive()
board = Board.get_default_board()

threshold = 0.5
bounce_count = 0

board.wait_for_button()

while True:
    left = reflectance.get_left()
    right = reflectance.get_right()

    if left > threshold or right > threshold:
        drivetrain.stop()
        bounce_count = bounce_count + 1
        print("Bounce", bounce_count)
        drivetrain.turn(180)
    else:
        drivetrain.set_effort(0.3, 0.3)
```

</TeacherNote>

<TeacherNote title="Differentiation & a lurking problem">

**More support:** start with just `if` (stop on the line) before adding the `else`
and the turn. **More challenge:** try `turn(90)` and observe; add `elif` for a third
case. Also plant the seed for Lesson 2-4: notice the robot keeps bouncing between the
*same two points* and never explores the rest of the circle — that predictability is
the problem randomness will fix next.

</TeacherNote>

## Every line is a pencil step

Read the SEARCH outline against Lesson 5-1. The loop is the rule you said out loud:
*take the oldest one; every neighbor with no number gets the next number*, except you
write where it came from instead of a number. `previous` starts with one row: the start
came from nowhere.

<Figure
  src="/img/lesson-m5-05/code-pencil.svg"
  alt="Seven lines of compute_bfs_path matched to the pencil method from Lessons 5-1 and 5-2. previous = {start: None} is the came-from table. to_visit = [start] is the to-visit list. current = to_visit.pop(0) takes the oldest one, from the front. if neighbor not in previous means it has no number yet. previous[neighbor] = current writes where it came from. to_visit.append(neighbor) adds it to the end. while current != start walks back along came-from and stops at the start."
  caption="Nothing in the function is new: each line is a step you already did with a pencil."
/>

`previous` does double duty. An intersection gets an entry only when it's reached, so
"is a key in `previous`" means "has a number." That's why `if neighbor not in previous`
is the whole numbered-once rule.

The list is a **queue**: `append()` adds to the end and `pop(0)` takes from the front
(index 0), so each ring is finished before the next one starts.

### Step 2 · The search

Add step 4, the loop. Put a temporary `print(previous)` right after it, and write a
throwaway `test_came_from()`: clear the blocked list, block `(1, 1)`, and call
`compute_bfs_path((0, 0), (2, 2))`. Set `ROWS` and `COLS` to 3 for a moment and run
it. The dictionary should match your Lesson 5-2 came-from table exactly, keys in the
same order. Put the settings back to 4 and remove the print; the test can stay.

If the destination is walled off, `to_visit` empties, the `while` ends, and
`destination` never appears in `previous`. Step 3 uses that.

### Step 3 · The walk-back

Steps 5 to 7: start at the destination and follow `previous` back to the start,
appending as you go. Then reverse, because you collected the path backwards; a list's
`reverse()` method does it in place.

Why `while current != start` and not `while current is not None`? Stopping *at* the
start means it is never appended: Rule 2 from Lesson 5-4, with no trimming. And
"already there" comes free: when `start == destination`, the loop never runs and
the path is `[]`.

Run `test_bfs_open()` again. The step counts should match now.

```python
def compute_bfs_path(start, destination):
    """Shortest path from start to destination around
    BLOCKED, as the list of intersections to drive to."""
    graph = build_graph(ROWS, COLS, BLOCKED)
    if start not in graph or destination not in graph:
        return []
    previous = {start: None}
    to_visit = [start]

    while len(to_visit) > 0:
        current = to_visit.pop(0)
        if current == destination:
            break
        for neighbor in graph[current]:
            if neighbor not in previous:
                previous[neighbor] = current
                to_visit.append(neighbor)

    if destination not in previous:
        return []
    path = []
    current = destination
    while current != start:
        path.append(current)
        current = previous[current]
    path.reverse()
    return path
```

`break` is "stop looking": it ends the `while` as soon as the destination comes off
the front. If yours differs but passes all five tests, keep yours.

## Activity · Break it on purpose

Once all five pass, break the function two ways. Put each back before the next.

1. **Change `pop(0)` to `pop()`.** Run Test 4 and count the steps: more. `pop()` takes
   the *newest* intersection, so the search dives down one path before finishing the
   ring, and the first route it finds may not be shortest. That is depth-first search:
   fine for other jobs, not this one.
2. **Delete `if neighbor not in previous:`** (keep the two lines under it, one indent
   level out). Run Test 1. Later, longer routes overwrite "came from" entries, and the
   walk-back can loop forever. If it hangs, press Ctrl-C. That one line is the
   numbered-once rule.

## The picture

`bfs_rings(start)` is the same search with no `break`, so it runs until every
reachable intersection has a number. Instead of came-from it records the ring number:
0 for the start, and `current`'s number plus one for each new neighbor. `print_grid()`
draws the result.

Write the body, then `test_rings()`: block `(1, 0)` and `(1, 1)` and call
`print_grid(ROWS, COLS, BLOCKED, bfs_rings((0, 0)))`:

```text
 3 |   3  4  5  6
 2 |   2  3  4  5
 1 |   1  X  5  6
 0 |   0  X  6  7
    -------------
       0  1  2  3
```

That's your Lesson 5-2 wall grid; Test 4's path is one route down these numbers,
1, 2, 3 … to the 7.

- Which line is "take the oldest one"? (`to_visit.pop(0)`.) What would `pop()` do? (Newest first — depth-first, not shortest.)
- Which line is "numbered once"? (`if neighbor not in previous`.)
- Why does the walk-back stop at `start`? (So the start is never appended — Rule 2.)
- Two cases return `[]`. What are they? (Already there; walled off.)

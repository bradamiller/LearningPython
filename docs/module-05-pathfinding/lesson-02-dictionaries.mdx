## What is a dictionary?

A **dictionary** stores **key-value pairs** in curly braces. Like a real dictionary maps
words to definitions, or a phone book maps names to numbers, a Python dictionary maps any
key to any value:

```python
scores = {"Alice": 95, "Bob": 87}
graph = {}                         # empty, ready to fill
graph[(0, 0)] = [(0, 1), (1, 0)]   # node (0,0) -> its neighbor list
```

For our graph, the **keys are node tuples** and the **values are lists of neighbor
tuples.** Why not just a list? Because we look things up by *content* — "what are the
neighbors of (1,1)?" — not by position. A dictionary jumps straight to the answer.

## Access and the `in` keyword

Look up a value with square brackets, and check whether a key exists with `in`:

```python
graph = {(0, 0): [(0, 1), (1, 0)], (0, 1): [(0, 0), (0, 2), (1, 1)]}

print(graph[(0, 0)])       # [(0, 1), (1, 0)]
print(len(graph[(0, 0)]))  # 2  -- number of neighbors

print((0, 0) in graph)     # True
print((2, 2) in graph)     # False -- not added
```

`in` matters a lot here: **a blocked node simply isn't in the graph**, so
`(1, 1) in graph` tells you whether that intersection is reachable. Accessing a *missing*
key with `graph[(9, 9)]` raises a `KeyError` — so check with `in` first.

One more thing you'll need: deleting a key. `del graph[(1, 1)]` removes the pair whose
key is `(1, 1)`; afterwards `(1, 1) in graph` is `False`.

## Activity · Build the graph automatically

Typing all 9 nodes of a 3×3 grid by hand is tedious; a 10×10 grid has 100. So
`build_grid_graph()` generates the graph for any size. Each node's neighbor list is
built the same way: check up, down, left and right, and add only the ones that are
actually on the grid. That means a **bounds check** before each `append` — only add
"up" if you're not already in the top row (`row > 0`), only add "down" if you're not
in the bottom row (`row < rows - 1`), and the same two checks for columns. The four
checks are what give corners 2 neighbors and interior nodes 4.

  caption="A failed check is a neighbor that would be off the grid, so it is never appended."
/>

## Activity · Removing blocked nodes

Blocking a node is a **two-step** job: delete its key, *and* remove it from every other
node's neighbor list. Forget the second step and other nodes still think they can reach a
blocked intersection — that's what the outline's two numbered steps are.

Step 2 is the one to think about. For each node still in the graph you need a *new*
neighbor list with the blocked ones left out. One way: start a new empty list, loop
over the old neighbors, and append each one that is `not in blocked_nodes`; then
assign the new list back to `graph[node]`.

Write the body, then a test — `test_remove_blocked()` — that builds a **3×3** graph,
removes `(1, 1)`, and prints how many intersections are left, `(1, 1) in graph`, and the
neighbors of `(0, 1)`. Predict all three first. Don't go on until both tests print what
you predicted.

<Reveal title="Check your two functions" hint="write and test both first">

```python
def build_grid_graph(rows, cols):
    """Return the open grid as a dictionary: every (row, col)
    maps to the list of its on-grid neighbors."""
    graph = {}
    for row in range(rows):
        for col in range(cols):
            neighbors = []
            if row > 0:            neighbors.append((row - 1, col))  # up
            if row < rows - 1:     neighbors.append((row + 1, col))  # down
            if col > 0:            neighbors.append((row, col - 1))  # left
            if col < cols - 1:     neighbors.append((row, col + 1))  # right
            graph[(row, col)] = neighbors
    return graph

def remove_blocked(graph, blocked_nodes):
    """Take every node in blocked_nodes out of graph: delete
    its key AND drop it from every other node's neighbors."""
    for node in blocked_nodes:          # step 1: delete the keys
        if node in graph:
            del graph[node]
    for node in graph:                   # step 2: clean neighbor lists
        graph[node] = [n for n in graph[node] if n not in blocked_nodes]
    return graph
```

The one-line list in step 2 is a **list comprehension** — "the list of every `n` in the
old neighbors for which `n` is not blocked." It's a shortcut for the loop-and-append
version; if you wrote the loop, keep it. And the 3×3 test should print `8`, `False`,
and `[(0, 0), (0, 2)]`.

</Reveal>

# The grid as a graph, in a dictionary: every intersection is
# a key, and its value is the list of neighbors it is joined
# to. The BFS PLANNER searches this graph. Starts with the
# open grid; Lesson 5-4 adds the blocked list, so a blocked

COLS = 4

def build_grid_graph(rows, cols):
    """Return the open grid as a dictionary: every (row, col)
    maps to the list of its on-grid neighbors."""
    graph = {}
    for row in range(rows):
        for col in range(cols):
            neighbors = []
            if row > 0:            neighbors.append((row - 1, col))  # up
            if row < rows - 1:     neighbors.append((row + 1, col))  # down
            if col > 0:            neighbors.append((row, col - 1))  # left
            if col < cols - 1:     neighbors.append((row, col + 1))  # right

    return graph

    """Take every node in blocked_nodes out of graph: delete
    its key AND drop it from every other node's neighbors."""
    for node in blocked_nodes:          # step 1: delete the keys
        if node in graph:
            del graph[node]
    for node in graph:                   # step 2: clean neighbor lists

    print("Intersections:", len(graph))          # 16

    print("Neighbors of (0, 0):", graph[(0, 0)])  # 2: a corner

def test_remove_blocked():
    graph = build_grid_graph(3, 3)

    print("Intersections:", len(graph))          # 8

## Wrap-up

- How is a dictionary different from a list? (Looked up by key, not by position.)
- Why are tuples the keys and lists the values in our graph? (A node is a fixed pair; its neighbors are a changing collection.)
- What are the two steps to block a node? (Delete its key; remove it from all neighbor lists.)

<TeacherNote title="Start simple; the two-step removal is the trap">

Show a plain dictionary (`{"name": "Alice"}`) before the tuple-keyed graph. Have students
open their Lesson 5-1 drawings and translate each node into a key-value pair — makes the

comprehension in the reveal is new; a plain loop-and-append is the version to expect

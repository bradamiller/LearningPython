## Python's dictionary

For the numbers, the key is an intersection and the value is its steps to D:

```python
distance = {}              # an empty dictionary
distance[(3, 3)] = 0       # store: key (3, 3), value 0
print(distance[(3, 3)])    # look up: 0
```

A key must be something that can't change, like a number or a tuple, so an `(x, y)`
tuple works.

  caption="The numbers on the grid, in a dictionary called distance."

<OptionalExtension title="Why a dictionary is fast" gate="Optional: open it if you have time. Nothing later depends on it.">

A printed dictionary is quick because it's in alphabetical order: you flip straight to the
right page. A Python dictionary is organized for speed too, though not alphabetically.
When you store a value, Python turns the key into a number that says where to keep it;
when you look the key up, it does the same arithmetic and goes straight there.

That trick is **hashing**. It's why a lookup is just as fast with four thousand entries as
with four, and why a key can't change: a changed key would send Python to the wrong place.

</OptionalExtension>

## Discuss · Where does the program keep the neighbors?

To visit an intersection, the program needs its open neighbors. On paper you just looked.
Take a 3×3 grid with the middle, (1,1), blocked.

<Figure
  src="/img/lesson-m5-01/graph-blocked-xy.svg"
  alt="The 3 by 3 grid with (1, 1) blocked: the intersection is crossed out and its four lines are removed, so (0, 1), (1, 0), (1, 2) and (2, 1) each have one neighbor fewer."
  caption="A 3×3 grid with (1,1) blocked."
/>

<TeacherNote title="Leading the discussion (10 min)">

The goal is the second dictionary, and the reason to build it before the search. Make the
case with blocked intersections, not speed: on a 4×4 grid nobody can feel the time.

</TeacherNote>

**Question 1.** The program is visiting (0,1). How could it work out (0,1)'s open
neighbors?

<Reveal title="Answer 1" hint="discuss first">

**Try all four directions,** left, right, down, up, and keep each one that is on the grid
and not blocked. Left of (0,1) is off the grid and (1,1) is blocked, so its open neighbors
are (0,0) and (0,2).

</Reveal>

<TeacherNote title="Question 1">

Let them say the two checks out loud: on the grid, and not blocked. Both have to be right
every time the search visits anything.

</TeacherNote>

**Question 2.** The search visits every intersection and does those checks every time.
Could the program do them once instead, before the search starts?

<Reveal title="Answer 2" hint="discuss first">

**Yes: work out every intersection's open neighbors once,** leaving out anything off the
grid and anything blocked. Then the search never checks for a blocked intersection again;
it just reads the list.

</Reveal>

<TeacherNote title="Question 2">

The win is one place for the blocked check instead of one inside the search. A search
that forgets it steps into the wall; a list that never had the wall in it can't. Lesson
5-4 builds the blocked intersections into the list.

</TeacherNote>

**Question 3.** How should the program save each intersection's neighbors, so the search
can look up (0,1)'s later?

<Reveal title="Answer 3" hint="discuss first">

**Another dictionary.** The key is the intersection, and the value is its list of open
neighbors: `graph[(0, 1)] = [(0, 0), (0, 2)]`.

</Reveal>

<TeacherNote title="Question 3">

This time they should get there fast: same tool, and the value is a list instead of a
number.

</TeacherNote>

## The grid as a graph

What that dictionary holds, every point and the points it's joined to, is what computer
scientists call a **graph**: a set of **nodes** (points) connected by **edges** (links). A
road map is one (intersections and streets), so is a social network (people and
friendships). (In computer science, "graph" never means a bar chart.)

Our grid is a graph. Every intersection is a **node**, named by its coordinate like
`(1, 2)`. Every line between adjacent intersections is an **edge**. A node's
**neighbors** are the nodes its edges lead to.

<Figure
  src="/img/lesson-m5-01/graph-3x3-xy.svg"
  alt="The 3 by 3 grid drawn as a graph: nine nodes labeled (x, y) with (0, 0) at the bottom-left, joined by edges to their neighbors left, right, below and above. The four corner nodes have 2 neighbors, the four edge nodes 3, and the center node 4."
  caption="Every intersection is a node; every line between neighbors is an edge. The shading counts neighbors."
/>

A **corner** has 2 neighbors, an **edge** node 3, an **interior** node 4.

<KnowledgeCheck
  question="On a 3×3 grid, how many neighbors does the interior node (1,1) have?"
  options={[
    {text: '2'},
    {text: '3'},
    {text: '4', correct: true},
    {text: '8'},
  ]}
  explanation="(1,1) connects left, right, down, and up — (0,1), (2,1), (1,0), (1,2). No diagonals, so four neighbors."
/>

A blocked intersection is **removed** from the graph: the node *and* all its edges, as in
the picture of (1,1) blocked above. So (0,1), (1,0), (1,2) and (2,1) each lose a neighbor.
That's the half people forget: a graph that still has an edge into (1,1) lets the search
step into the wall.

<KnowledgeCheck
  question="After (1,1) is blocked, how many neighbors does (0,1) have?"
  options={[

    {text: '2 — it lost its connection to the right, to (1,1)', correct: true},
    {text: '4'},
    {text: '0'},
  ]}
  explanation="(0,1) used to connect to (0,0), (0,2), and (1,1). With (1,1) removed, only two neighbors remain."
/>

This lesson builds the open grid; Lesson 5-4 takes the blocked intersections out.

Of the first three lines, only the count changes: `(1, 1)` and `(0, 0)` have the same
neighbors on any grid at least 3×3. The loop prints 16 lines in the order they were
added, the order of your two loops. The four corners have 2 neighbors, the eight edge
intersections 3, and the four in the middle 4.

```python
def build_grid_graph(rows, cols):
    """Return the open grid as a dictionary: every (x, y)
    maps to the list of its on-grid neighbors."""
    graph = {}
    for x in range(cols):
        for y in range(rows):
            neighbors = []
            if x > 0:              neighbors.append((x - 1, y))  # left
            if x < cols - 1:       neighbors.append((x + 1, y))  # right
            if y > 0:              neighbors.append((x, y - 1))  # down
            if y < rows - 1:       neighbors.append((x, y + 1))  # up
            graph[(x, y)] = neighbors
    return graph
```

```python
# ===== GRID GRAPH =====
# The grid as a graph, in a dictionary: every intersection is
# a key, and its value is the list of neighbors it is joined
# to. The BFS PLANNER searches this graph. Starts with the
# open grid; Lesson 5-4 adds the blocked list, so a blocked
# intersection is neither a key nor anyone's neighbor.
ROWS = 4                 # the grid is ROWS x COLS intersections
COLS = 4

def build_grid_graph(rows, cols):
    """Return the open grid as a dictionary: every (x, y)
    maps to the list of its on-grid neighbors."""
    graph = {}
    for x in range(cols):
        for y in range(rows):
            neighbors = []
            if x > 0:              neighbors.append((x - 1, y))  # left
            if x < cols - 1:       neighbors.append((x + 1, y))  # right
            if y > 0:              neighbors.append((x, y - 1))  # down
            if y < rows - 1:       neighbors.append((x, y + 1))  # up
            graph[(x, y)] = neighbors
    return graph

def test_grid_graph():
    graph = build_grid_graph(ROWS, COLS)
    print("Intersections:", len(graph))          # 16
    print("Neighbors of (1, 1):", graph[(1, 1)])  # 4 of them
    print("Neighbors of (0, 0):", graph[(0, 0)])  # 2: a corner
    for node in graph:                            # the whole graph,
        print(node, graph[node])                  # one line per node

# ===== RUN =====

test_grid_graph()
```

## Wrap-up

- Why does the program keep the numbers in a dictionary, not a list? (It looks them up by intersection, not by position.)
- What does `(2, 2) in distance` ask? (Does (2,2) have a number yet?)
- Why work out every intersection's neighbors before the search? (Blocked intersections are left out once, so the search never has to check for them.)
- What does blocking a node remove? (The node and all its edges, so it is nobody's neighbor.)

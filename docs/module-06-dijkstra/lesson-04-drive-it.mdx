Two planners, one grid, one trip. The robot drives from (0, 0) to (0, 3) planned by
BFS, and then the same trip planned by Dijkstra, and the class times both. BFS takes

4's `drive_path()`, with the planner's name the only Module 6 line in the program.

## One name changes

The program is Module 4's driving toolkit plus Module 6's two planners. The main
program chooses:

```python
SLOW_SEGMENT = ((0, 1), (0, 2), 5)          # what you measured in Lesson 6-1
add_slow_edge(SLOW_SEGMENT[0], SLOW_SEGMENT[1], SLOW_SEGMENT[2])

position = (0, 0)
heading = 0
destination = (0, 3)

PLANNER_NAME = "BFS"          # or "Dijkstra" -- change this between runs

if PLANNER_NAME == "Dijkstra":
    planner = compute_dijkstra_path
else:
    planner = compute_bfs_path
```

Then, before the button, print *both* plans — so the comparison is on the screen before
either run happens:

```python
for (name, p) in [("BFS", compute_bfs_path), ("Dijkstra", compute_dijkstra_path)]:
    path = p(position, destination)
    print(name.ljust(9), "steps:", len(path), " cost:", path_cost(position, path), " ", path)

path = planner(position, destination)
board.wait_for_button()

start_time = time.time()
position, heading = drive_path(path, position, heading)
elapsed = time.time() - start_time

print(PLANNER_NAME, "took", round(elapsed, 1), "seconds for", len(path), "steps")
```

```
BFS       steps: 3  cost: 7   [(0, 1), (0, 2), (0, 3)]
Dijkstra  steps: 5  cost: 5   [(1, 0), (1, 1), (1, 2), (0, 2), (0, 3)]
```

`planner = compute_dijkstra_path` is the Lesson 5-6 swap: a function handed around by
name. `drive_path()` is handed a list of intersections and has no idea which planner
produced it.

## Activity · Two runs, one stopwatch

1. Type your measured slow segment into `SLOW_SEGMENT`. Check the printed costs
   match what you worked out on paper in Lesson 6-1.
2. `PLANNER_NAME = "BFS"`. Read the printed path, press the button, start a stopwatch
   with the robot. Record the time. Watch it take the slow road.
3. `PLANNER_NAME = "Dijkstra"`. Same start, same destination. Record the time. Watch it
   go round.
4. Fill in the table:

```
Planner    steps   cost   seconds
BFS         ___    ___     ___
Dijkstra    ___    ___     ___
```

The program's own `elapsed` is a check on your stopwatch. The two should tell the same
story: more steps, fewer seconds.

<TeacherNote title="Make it a class event">

Run the two trips back to back with the whole class watching and one student on a
stopwatch. The robot visibly choosing the long way round and arriving sooner is the
module's payoff; let it land before the discussion.

Before the button, have students read both printed plans aloud and predict the two
times from the costs and the per-block time they measured in 6-1. Then compare.
Discrepancies are a good conversation: turns cost time too (the detour has more of
them), which is why the predicted gap is usually a little bigger than the measured
one. That is also a fair place to mention what the course left out — a planner that
weights turns needs to know the heading, and that is a bigger change than two lines.

If the two plans match, the slow segment is missing or too light. Fix the setup, not
the code.

</TeacherNote>

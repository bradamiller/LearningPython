This lesson is for students who built the `Manhattan` and `BFS` classes in Lessons 4-5
and 5-5. It adds the third one, `Dijkstra`, and runs all three as objects through the
Module 5 class harness. The harness never finds out which one it is holding. That
property has a name — **polymorphism** — and this is the cleanest place in the course
to see it. If you did Lesson 6-3 as a function, this lesson replaces that function with
the class; if you skipped ahead from 6-3, this is where you write it.

## The third class

`BFS` from Lesson 5-5 holds its blocked list in `self.blocked` and exposes
`add_blocked()`, `clear_blocked()` and `compute_path(position, destination)`. `Dijkstra`
is a copy of it with one more list and the two changes. Same shape as the other two:
`compute_path(position, destination)`, told the position every call, returning a path
that excludes the start. The slow list is the planner's own data, as the blocked list
already was, so nothing outside the object reaches in to change it.

The name under the class is the Lesson 5-5 rule again: one object called `planner`,
and it is your newest planner. Delete `planner = BFS()`, and everything in Module 5
that said `planner.` now plans by cost — on a grid with no slow edges, it gives the
same answers as before, which you can prove by running any Module 5 test.

## One harness, three objects

The Lesson 5-6 class harness is handed an object and calls its methods:

```python
run_all_tests("Manhattan", Manhattan())
run_all_tests("BFS",       BFS())
run_all_tests("Dijkstra",  Dijkstra())
```

Inside, every line is `planner.compute_path(position, destination)`,
`block(planner, ...)` or `clear(planner)`. Nothing in the harness names a class. The
seventh case needs one more helper of the `block()` kind — `slow(planner, a, b, cost)`
tells the planner about a slow edge *and* records it in `SLOW_EDGES`, so that
`path_cost()` adds up the true weights whichever planner is being tested — and
`clear()` has to forget the slow edges as well as the blocks, on both sides. Paste
these under `clear()` in the 5-6 part of the file, and make the three edits:

```python
def slow(planner, a, b, cost):
    """Tell planner about the slow edge AND note it in
    SLOW_EDGES, so path_cost() can see it."""
    pass
```

1. `clear(planner)` also calls `planner.clear_slow_edges()` and `clear_slow_edges()`.
2. In `run_all_tests()`, the seventh case: `slow(planner, (0, 1), (0, 2), 5)` where it
   said `add_slow_edge(...)`, `planner.compute_path(...)` for the plan, and
   `clear(planner)` for both clears.
3. `compare()` makes a fresh `BFS()` and a fresh `Dijkstra()`, and a fresh object knows
   nothing — so before it plans, each one is told every entry in `SLOW_EDGES` with
   `p.add_slow_edge(a, b, cost)`. Two lines, and `BFS` ignores them.

That `slow()` call, and `clear()`'s, mean `Manhattan` and `BFS` need an
`add_slow_edge()` and a `clear_slow_edges()` too, even though they ignore them,
exactly as `Manhattan.add_blocked()` did nothing in Module 5:

```python
class BFS:
    # ...
    def add_slow_edge(self, a, b, cost):
        pass        # BFS does not plan by cost; it accepts the call and ignores it

    def clear_slow_edges(self):
        pass
```

Three classes, one set of method names, one harness that works on any of them. That is
polymorphism: code written against a *shape* — the names a planner answers to — rather
than against one particular class. You have been using it since Lesson 5-6, where the
harness was handed a function. Objects make the shape explicit: it is the list of
methods.

# One Dijkstra object holds the grid size, ITS OWN blocked
# list and ITS OWN slow list, and plans by cost around both:
# the BFS class with the slow-list methods added and the two
# Lesson 6-3 changes inside compute_path(). Same names as the
# function version, with planner. in front; the 5-6 class

def closest(intersections, distance):
    """Return the entry of intersections with the smallest
    value in distance: a plain find-the-minimum loop."""
    best = intersections[0]
    for node in intersections:
        if distance[node] < distance[best]:
            best = node
    return best

class Dijkstra:
    def __init__(self, rows=4, cols=4):
        self.rows = rows
        self.cols = cols
        self.blocked = []
        self.slow_edges = []

    def add_blocked(self, intersection):
        if intersection not in self.blocked:
            self.blocked.append(intersection)

    def clear_blocked(self):
        self.blocked = []

    def add_slow_edge(self, a, b, cost):
        self.slow_edges.append((a, b, cost))

    def clear_slow_edges(self):
        self.slow_edges = []

    def weight(self, a, b):
        for (x, y, cost) in self.slow_edges:
            if (a == x and b == y) or (a == y and b == x):
                return cost
        return 1

    def compute_path(self, position, destination):
        graph = build_graph(self.rows, self.cols, self.blocked)
        if position not in graph or destination not in graph:
            return []
        previous = {position: None}
        distance = {position: 0}
        to_visit = [position]

        while len(to_visit) > 0:
            current = closest(to_visit, distance)
            to_visit.remove(current)
            if current == destination:
                break
            for neighbor in graph[current]:
                new_distance = distance[current] + self.weight(current, neighbor)
                if neighbor not in distance or new_distance < distance[neighbor]:
                    distance[neighbor] = new_distance
                    previous[neighbor] = current
                    if neighbor not in to_visit:
                        to_visit.append(neighbor)

        if destination not in previous:
            return []
        path = []
        current = destination
        while current != position:
            path.append(current)
            current = previous[current]
        path.reverse()
        return path

planner = Dijkstra()

def dijkstra_distances(position):
    """Cheapest cost to every reachable intersection, as a
    dictionary -- the search with no break, like bfs_rings()."""
    graph = build_graph(ROWS, COLS, planner.blocked)
    if position not in graph:
        return {}
    distance = {position: 0}
    to_visit = [position]
    while len(to_visit) > 0:
        current = closest(to_visit, distance)
        to_visit.remove(current)
        for neighbor in graph[current]:
            new_distance = distance[current] + planner.weight(current, neighbor)
            if neighbor not in distance or new_distance < distance[neighbor]:
                distance[neighbor] = new_distance
                if neighbor not in to_visit:
                    to_visit.append(neighbor)
    return distance

def compare(position, destination):
    """Print BFS's and Dijkstra's answers for one trip:
    steps, cost and path, one line each."""

        print(" ", "{:<9}".format(name), "steps:", len(path),

<TeacherNote title="Polymorphism, named once, after students have used it twice">

The word is introduced here because students have now *done* the thing three times:
the Lesson 5-6 function swap, the Lesson 5-6 class extension, and this. Name it, point
at the harness, and move on; a lecture on OOP terminology would undo the lightness that
made the class track work.

The `add_slow_edge()` that does nothing is the teaching moment. Ask why it has to exist
and let students find the `if planner is BFS` they'd otherwise need in the harness.
`compare()`'s two new lines make the same point from the other side: a planner that
cannot use the slow list is still *told* it, and nothing checks which one it is.

Everything else is Lesson 6-3 with `self.` in front. Students who did 6-3 carefully
finish this in half an hour. The one trap is `planner = BFS()` left in the file below
the Dijkstra one, which silently puts the old planner back; the Lesson 5-5 rule — one
object called `planner` — is worth repeating.

</TeacherNote>

## Wrap-up

- What does `Dijkstra` add to `BFS`? (A slow list with three methods, and the two changes.)
- Why can one harness test three classes? (They answer to the same method names.)
- What is that called? (Polymorphism.)

Reaching the *first* intersection is easy. Reaching the *third* is the same two calls,
three times — and that is what a `for` loop is for. This lesson turns "arrive at an
intersection" into a building block you can repeat a chosen number of times, and
looks closely at why the second call works at all.

<Objectives>

By the end of this lesson you will be able to:

- Explain why `track_to_intersection()` called twice in a row would not move the robot without `drive_past_intersection()` between them
- Drive past one intersection to reach the next
- Use a `for` loop to drive a chosen number of intersections
- Write a `drive_intersections(count)` helper and use it

</Objectives>

## Why the second call works

Try a thought experiment. Suppose you called `track_to_intersection()` twice in a row
with nothing in between. The first call stops with both sensors on the cross. The second
call's loop condition — `not is_at_cross()` — is already `False`, so the loop body never
runs: the robot "arrives" instantly, without moving.

That is the second job of `drive_past_intersection()`, the one Lesson 2-9 mentioned.
Driving 8.75 cm forward parks the wheels on the intersection, *and* carries the sensors
past the tape onto plain line. Now the next `track_to_intersection()` has a line to follow
and a new cross to find.

So the pattern for driving across the grid is just the arrival pair, repeated:
**track, drive past, track, drive past, …** — and because the drive-past parks the
wheels on the intersection, the robot always ends up sitting on the last one, ready to
turn.

## Drive a set number with a `for` loop

Writing the pair out by hand for each intersection is repetitive. A `for` loop repeats
it a chosen number of times:

```python
# (both Module 2 toolkits go above)

board = Board.get_default_board()

board.wait_for_button()

intersections = 3

for i in range(intersections):
    print("Driving to intersection", i + 1)
    track_to_intersection()
    drive_past_intersection()

print("Done! Parked on intersection", intersections)
```

Nothing in the loop body changes from one pass to the next — the only thing `i` is
used for is the print. And there is no special case for the last intersection: the
drive-past parks the robot on it, which is exactly where you want to be.

  explanation="The name says what the sensors do, not the wheels. The sensors end up past the cross; the wheels end up on it. Every arrival ends the same way, last one included."

<TeacherNote title="The off-by-one is gone; the thought experiment is the lesson">

Older versions of this lesson taught a timed nudge after each intersection, with an
`if i < count - 1` guard to skip it on the last one. The toolkit's
`drive_past_intersection()` replaces both: it is a fixed distance, and it parks the
wheels on the cross rather than past it, so there is nothing to skip. Spend the saved
time on the thought experiment at the top — trace two `track_to_intersection()` calls
with no drive-past on the board and have students say why the second one returns at
once. Then walk the loop with `i = 0, 1, 2` and have them say where the robot is after
each pass.

</TeacherNote>

## Activity · Write the helper

You'll drive runs of intersections constantly from here on, so wrap the loop in a
function. Write `drive_intersections(count)` yourself: one parameter, a `for` loop, the
arrival pair inside it, and a print so you can follow along. Then replace the loop in
your program with a single call, `drive_intersections(3)`, and run it.

<Reveal title="Compare with one version" hint="write yours first">

```python
def drive_intersections(count):
    for i in range(count):
        print("  Intersection", i + 1, "of", count)
        track_to_intersection()
        drive_past_intersection()
```

If yours has an `if` in it, ask what it is guarding against — and whether
`drive_past_intersection()` actually drives the robot past anything.

</Reveal>

Now `drive_intersections(4)` drives four segments in one clean line — a building block
you'll lean on in the next two lessons, and the same shape as `polygon()` from
Module 1: a loop and a count, packaged.

## Wrap-up

- Why does `drive_past_intersection()` have to come between two tracks? (The sensors are still on the cross; the second track would return at once.)
- What loop drives a set number of segments? (A `for` loop over `range(count)`, with the arrival pair inside.)
- Where is the robot after the last pass? (Parked on the last intersection — the drive-past puts the wheels on it.)

Reaching the *first* intersection is easy. Reaching the *third* is the same call,
three times — and that is what a `for` loop is for. This lesson turns "arrive at an
intersection" into a building block you can repeat a chosen number of times — the
first real function in the GRID DRIVING section.

<Objectives>

By the end of this lesson you will be able to:

- Drive through one intersection to reach the next
- Use a `for` loop to drive a chosen number of intersections
- Write `drive_intersections(count)` from its docstring, test it, and use it

</Objectives>

    with the sensors past it, ready to turn or to go on."""
    pass

def test_two_by_hand():
    # track_to_intersection() written out twice, no loop: the
    # robot should end parked on the SECOND intersection
    pass

def test_drive_run():

    pass

The function has a **docstring** (Lesson 1-12) instead of step comments: the string
under the `def` line says what the function does and what ends it, and that's all
the help you get. The steps are yours to work out — this page tells you enough to.
Keep the docstring when you write the body; it belongs to the function.

## Drive a set number with a `for` loop

Two calls in a row reach two intersections: each one ends with the sensors past the
tape (Lesson 2-8), so the next has a line to follow. But writing the call out by hand
for each intersection is repetitive, and it's wrong the moment you want a different
number. A `for` loop over `range(count)` repeats it a chosen number of times — the same shape as `polygon()` in Module 1, a loop and a
count, packaged into a function with the count as its parameter.

Nothing in the loop body changes from one pass to the next; the only thing the loop
variable is good for is the print ("Intersection 1 of 3", and so on — remember it
starts at 0). And there is no special case for the last intersection: each call ends
with the robot's center on the cross, which is exactly where you want to be.

<TeacherNote title="No special case for the last intersection">

Older versions of this lesson taught a timed nudge after each intersection, with an
`if i < count - 1` guard to skip it on the last one. `track_to_intersection()` now
ends with the robot's center on the cross, so there is nothing to skip. Walk the loop
with `i = 0, 1, 2` on the board and have students say where the robot is after each
pass.

</TeacherNote>

### Step 1 · test_two_by_hand()

Write the body: `track_to_intersection()` twice, no loop, and a print at the end. Set
the run line to `test_two_by_hand()` and run it. The robot should end parked on the
*second* intersection. Don't go on until it does.

### Step 2 · drive_intersections(count)

Now write the function from its docstring: one parameter, a `for` loop over it,
`track_to_intersection()` inside, and a print so you can follow along. Write the body of
`test_drive_run()` — one call, `drive_intersections(3)`, and a print — set the run
line to it, and run. The robot should arrive three times, printing each one, and end
parked on the third intersection.

<Reveal title="Check your drive_intersections()" hint="write and test it first">

```python
def drive_intersections(count):
    """Arrive at count intersections in a row, printing
    which one it is each time. Ends parked on the last one
    with the sensors past it, ready to turn or to go on."""
    for i in range(count):
        print("  Intersection", i + 1, "of", count)
        track_to_intersection()
```

If yours has an `if` in it, ask what it is guarding against. The two tests are
`track_to_intersection()` twice, and `drive_intersections(3)` followed by a print.

</Reveal>

Now `drive_intersections(4)` drives four segments in one clean line — the building
block the next two lessons are made of.

<TeacherNote title="Solution (teacher copy)">

This lesson's addition to the GRID DRIVING section of `robot.py`, plus the run block;
the rest of the file is as the Lesson 3-1 teacher copy left it. The whole file at
the end of the module is in the [Module 3 sample programs](/teacher-guide/sample-programs/module-3). Class-track
students write `tracker.track_to_intersection()` inside the helper; the helper itself stays a plain
function in this section.

```python
# --- Lesson 3-2: a run of intersections ---
# drive_intersections(count) is track_to_intersection() in a
# loop.
# It ends parked on the count-th intersection, so Lessons 3-3
# and 3-4 build every path out of it and the two turns.

def drive_intersections(count):
    """Arrive at count intersections in a row, printing
    which one it is each time. Ends parked on the last one
    with the sensors past it, ready to turn or to go on."""
    for i in range(count):
        print("  Intersection", i + 1, "of", count)
        track_to_intersection()

def test_two_by_hand():
    track_to_intersection()
    track_to_intersection()
    print("Parked on the second intersection")

def test_drive_run():
    drive_intersections(3)
    print("Done! Parked on intersection 3")

# ===== RUN =====
board.wait_for_button()
test_drive_run()
```

</TeacherNote>

## Wrap-up

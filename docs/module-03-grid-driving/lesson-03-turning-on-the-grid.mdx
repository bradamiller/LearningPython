You can drive straight down the grid. Now you'll turn corners — sequencing drives and
turns to trace an **L-shaped path**. Any route across a grid is really just a
sequence of "drive some segments, turn, drive some more."

<Objectives>

By the end of this lesson you will be able to:

- Sequence drive and turn operations into a path
- Turn at intersections with `turn_right()` and `turn_left()`
- Navigate an L-shaped path
- Plan a path on paper before you write the code

</Objectives>

## Drive, turn, drive

Turning a corner on the grid is just like walking city streets: go to the
intersection, then turn. In code that's `drive_intersections()`, then a turn, then
`drive_intersections()` again:

```python
drive_intersections(tracker, 2)   # drive forward 2 intersections
tracker.turn_right()              # turn right onto the crossing line
drive_intersections(tracker, 2)   # drive 2 more, now sideways

print("L-shape complete!")
```

## No clearing after a turn

There's a nice detail: after `turn_right()` or `turn_left()`, you go **straight into**
the next drive — no clearing needed. That's because the turn methods already drive
forward off the intersection as part of turning, so the robot is past the cross when
the turn finishes.

<KnowledgeCheck
  question="After tracker.turn_right(), do you need to clear the intersection before the next drive_intersections()?"
  options={[
    {text: 'Yes — always clear before driving'},
    {text: 'No — the turn already moves the robot off the intersection', correct: true},
    {text: 'Only on the last turn'},
    {text: 'Only if the battery is low'},
  ]}
  explanation="turn_right() and turn_left() drive forward as part of turning, so the robot has already cleared the cross — go straight into the next drive."
/>

<TeacherNote title="Two rules that trip students up">

Reinforce two things: (1) the robot must be **at an intersection** to turn — you
can't turn mid-segment; and (2) you clear *before* the next drive when going
straight through, but you **don't** clear after a turn (the turn cleared for you).
Getting these two backwards is the source of most "my path is off by one
intersection" bugs.

</TeacherNote>

## Activity · Plan on paper first

Before coding a path, sketch it: mark the start, the direction the robot faces, how
many segments each leg is, and where the turns go. Then translate the sketch,
one leg per line:

```python
drive_intersections(tracker, 3)   # leg 1
tracker.turn_left()               # corner
drive_intersections(tracker, 1)   # leg 2
```

<TeacherNote title="Differentiation">

**More support:** give students a drawn path and have them write the matching
sequence. **More challenge:** a U-turn path (drive, turn right, drive one, turn
right, drive) — a good reminder that two right turns only reverse direction if you
drive a segment between them. Encourage planning on paper first; it prevents most
sequencing mistakes.

</TeacherNote>

## Wrap-up

- What's the basic shape of any grid path? (A sequence of drives and turns.)
- Do you clear after a turn? (No — the turn already cleared the intersection.)
- Where must the robot be to turn? (At an intersection.)
